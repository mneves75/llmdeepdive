## Closed the img2threejs blockout loop without adopting it

Root-caused the stalled silhouette gate. The reference image is a near-parallel
column — constant width through the whole stack — while the review harness
rendered at fov 35, so the render tapers with depth. That is a lens mismatch,
not a geometry defect, and no amount of reshaping closes it. Three correction
loops of real edits to `TransformerScene` were driven by a broken measurement.

Two lessons worth keeping:

- **The concept render is intent, not a contract.** Chasing its silhouette added
  a *third* residual bypass route. A decoder block has exactly two, each starting
  at the input of the sub-layer it skips. A teaching product shipped an
  architecture that does not exist because a picture looked better with it.
  `tests/transformer-scene.test.mjs` now pins the route set.
- **Verify the artifact, not the harness.** Every loop rendered through
  `.img2threejs/review.ts` — its own camera, lights and framing, and no floor.
  Nobody opened `/explore/`. Doing so immediately exposed that the
  re-proportioned model outgrew `FIT_SIZE` and sank through the stage floor.
  `src/lib/three/envelope.ts` now publishes that envelope and a test asserts it.

Also worth noting: the skill's stock Tier 1 threshold (`0.85`) was stricter than
this spec's own blockout acceptance (`targetFidelity 0.7`). That conflict should
have been surfaced at loop 1 rather than after the loop budget was spent.

## Release 0.2.0

Gates run before shipping, all green: 22/22 tests, `astro check` 0 errors,
`ast-grep scan` clean, `pnpm audit --audit-level=high` no known vulnerabilities,
`wrangler deploy --dry-run` reports `No bindings found`, gitleaks finds no leaks
across all 30 commits of history.

Security work in this release:

- Dropped `blob:` from `worker-src`. Verified rather than assumed: `pagefind.js`
  constructs `new Worker(workerUrl)` with no `Blob`/`createObjectURL` anywhere,
  and search returns results under the real generated policy.
- Exercised the generated CSP against home, `/explore/` and a pt-BR lesson by
  injecting `dist/_headers` as a `<meta>` at document-start — zero violations.
  The first attempt injected outside `<head>`, so Chrome ignored the policy and
  the run proved nothing; the log said so. A green run whose harness was broken
  is worse than no run.
- Pruned unreferenced Pagefind UI bundles from `dist/` — unused JavaScript with
  `innerHTML` sinks that was being uploaded on every deploy.

## Process note

Two agent sessions were editing this tree at the same time. The second one had
already staged a commit (`git add -A`) while the first was still analysing. The
tell was `scripts/gen-headers.mjs` appearing in `git status` ninety seconds after
a status that did not list it. In a shared tree, re-read `git status` before
every mutation and never assume the diff you reviewed is the diff you commit.

`autoreview` needed three attempts to say anything: it refuses binary diffs
(the concept PNGs), it refuses truncated bundles (untracked files over 180 KB —
the same PNGs), and it shells out to bare `codex`, which lands on the exhausted
personal account and exits without output. Run it with
`CODEX_HOME="$(codex-auto home)"` and with large binaries out of the tree.

## Shipped 0.2.0 to production

Deploy was blocked first: the wrangler session was authenticated as
`conhecendo.contato@gmail.com` (account `f1bae7e4`) while the workers live in
`534f5829`, which surfaces as the unhelpful `Authentication error [code: 10000]`
rather than anything naming the account. `wrangler whoami` prints the account
list — compare it against the ID in the failing API URL before assuming scopes
or an expired token.

Staging then earned its keep twice.

- The pt-BR 404 fix **did not work**, having passed every local gate. Under
  `html_handling: "auto-trailing-slash"` Cloudflare 307-redirects `/file.html`
  to `/file`, and the surviving `404/index.html` claimed `/pt-br/404/`, so the
  not-found walk never matched the literal filename. Deleting the directory form
  fixed it. A build-time fix cannot be validated by a build-time gate when the
  asset router decides the outcome.
- A `Permissions-Policy` header looked missing and was not — the check had read
  a cached edge response. Cache-bust every canary request.

Production verified live: `worker-src 'self'` (the old policy had `blob:`, so
the header itself proves the new version is serving), `browsing-topics` denied,
both 404s correct in their own language, `pagefind-ui.js` gone while
`pagefind.js` still 200s, `robots.txt`, `www` 200, and the explorer CTA
resolving to a real lesson page with the right page marker.

## Cloudflare injects script this repo never wrote

The production browser canary produced the session's only console errors:
`static.cloudflareinsights.com/beacon.min.js`, injected at the edge by Web
Analytics automatic setup and blocked by the CSP. It is in no build artefact and
invisible to `curl` unless the request carries browser `User-Agent` and `Accept`
headers.

Considered and rejected: `Cache-Control: public, no-transform` on HTML. It does
block edge injection, and it also disables the CDN's Brotli/gzip on those
responses — the directive forbids intermediaries from transforming the body, and
Cloudflare is an intermediary. Uncompressed HTML costs far more than the console
error it removes. WooCommerce shipped exactly this and un-compressed its users.

The real fix is `auto_install: false` on the RUM site, which is an account
setting and remains open. Not a leak: CSP stops the script executing, so no
beacon data is ever sent. It is a dead config plus console noise.
