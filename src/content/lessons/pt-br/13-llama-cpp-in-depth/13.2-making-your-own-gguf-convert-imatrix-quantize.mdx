A lição 7.13 ensinou a julgar uma quantização feita por outra pessoa. Esta lição faz uma, em quatro passos, com uma conferência depois de cada um. Todos os comandos abaixo foram executados no llama.cpp na tag `b11380`, num substituto pequeno, o Qwen3-0.6B, porque uma receita que você não consegue repetir em minutos não ensina nada. A receita não foi executada no Qwen3.8-27B. Os caminhos são marcadores.

## Escreva primeiro como isso falha

Cinco coisas dão errado, então os comandos se protegem de cada uma:

1. O conversor não conhece a arquitetura. Rode `python convert_hf_to_gguf.py --print-supported-models` antes de baixar qualquer coisa.
2. Você quantiza um arquivo já quantizado. O `llama-quantize` recusa: `requantizing from type q4_K is disabled`. A flag `--allow-requantize` existe, e o README avisa que ela "pode reduzir severamente a qualidade" (tradução nossa).
3. Você pede um tipo de poucos bits sem matriz. O `IQ2_XXS` termina com `this quantization requires an imatrix!`.
4. Você calibra e pontua no mesmo texto.
5. Você confia num número de uma execução.

## Os quatro passos

```
python convert_hf_to_gguf.py MODEL_DIR --outtype bf16 --outfile model-bf16.gguf
llama-imatrix -m model-bf16.gguf -f calib.txt -o imatrix.gguf -ngl 99
llama-quantize --imatrix imatrix.gguf model-bf16.gguf model-Q4_K_M.gguf Q4_K_M
llama-perplexity -m model-bf16.gguf -f wiki.test.raw --kl-divergence-base base.kld --chunks 20 -ngl 99
llama-perplexity -m model-Q4_K_M.gguf -f wiki.test.raw --kl-divergence-base base.kld --kl-divergence --chunks 20 -ngl 99
```

**Converter.** Escreva sempre primeiro o arquivo sem perdas (`bf16`, ou `auto` para o tipo de 16 bits de maior fidelidade). Todo passo seguinte lê esse arquivo. A conversão do Qwen3-0.6B escreveu 311 tensores e um arquivo de 1,5 GB.

**Coletar.** A matriz é a soma das ativações ao quadrado por coluna de tensor, como a lição 7.13 explicou. No b11380 a saída vai por padrão para `imatrix.gguf`. Só `--output-format dat` escreve o formato legado. Um nome `.dat` sozinho ainda escreve GGUF e emite um aviso. O texto de calibração aqui foi a documentação do llama.cpp e os READMEs das ferramentas, 523.956 bytes, o que deu 305 chunks de 512 tokens. Para o seu modelo, use texto parecido com o seu tráfego, no formato de chat que você serve (`--parse-special` lê tokens especiais no texto).

O README mostra `llama-imatrix --in-file imatrix.gguf --show-statistics`. Tanto o b11380 quanto o build 11146 do Homebrew responderam `error: --model is required`. Acrescente `-m model-bf16.gguf` e funciona; a tabela sai em stderr. Ela mostra a soma das ativações ao quadrado por tensor e, neste modelo, varre ordens de grandeza: 15,68 para `attn_k` na camada 1 contra 192.029,52 na camada 26.

**Quantizar.** As sobrescritas são expressões regulares sobre nomes de tensores. A execução acrescentou `--tensor-type attn_v=q6_k --token-embedding-type q8_0`, e o log confirmou `applying manual override: q4_K -> q6_K` por camada.

O README lista mais botões. `--pure` desliga as misturas dos k-quants e usa um único tipo em tudo, `--leave-output-tensor` mantém o `output.weight` sem quantizar, e `--include-weights` ou `--exclude-weights` limita a matriz a tensores nomeados (os dois não se misturam). O `llama-imatrix` pula o `output.weight` por padrão, porque o README diz que em geral é melhor não aplicar a matriz ali; `--process-output` muda isso.

**Medir.** A primeira execução do perplexity grava uma vez os logits do bf16. A segunda compara cada candidato com eles.

A procedência é barata, então guarde-a. No arquivo feito com matriz, o `llama-gguf` listou as chaves de metadados `quantize.imatrix.file`, `quantize.imatrix.dataset`, `quantize.imatrix.entries_count` e `quantize.imatrix.chunks_count`, e o arquivo sem matriz não tinha nenhuma delas. Guarde o arquivo bf16, porque toda receita nova parte dele. Escreva o comando exato, o build e o corpus de calibração ao lado de qualquer arquivo que você compartilhar, para que um leitor possa repeti-lo.

## O que a execução mostrou

| Qwen3-0.6B, 20 chunks do teste do Wikitext-2 | Tamanho dos tensores quantizados | Divergência KL média | Mesmo token no topo |
|---|---|---|---|
| Q4_K_M, sem matriz | 456,11 MiB | 0,1036 ± 0,0022 | 83,3 % |
| Q4_K_M, imatrix | 456,11 MiB | 0,0689 ± 0,0016 | 85,8 % |
| imatrix, `attn_v` em Q6_K, embeddings em Q8_0 | 533,91 MiB | 0,0616 ± 0,0014 | 86,3 % |

A referência bf16 imprimiu perplexidade 23,6783 ± 1,12824 na execução que gravou seus logits, e os relatórios de KL imprimem `Mean PPL(base)` 23,405638 ± 1,096843 nos mesmos 20 chunks. Os tamanhos da tabela são o `quant size` do próprio quantizador; em disco os arquivos tinham 461,8 e 539,6 MiB. A matriz não custou byte nenhum e removeu cerca de um terço da divergência KL. As sobrescritas compraram um ganho menor por 78 MiB, na maior parte a tabela de embeddings, que é grande num modelo de 0,6B. Se essa troca vale a pena depende do seu modelo e da sua memória.

Por que divergência KL? O README do perplexity separa as duas. A perplexidade pergunta quão bem o modelo prevê um texto. A divergência KL, e estatísticas como a fração de tokens em que os dois modelos escolhem o mesmo token no topo, perguntam o quanto a distribuição quantizada se afastou da original. O README também avisa que os valores de perplexidade do llama.cpp "não são diretamente comparáveis" (tradução nossa) aos de outros projetos, nem entre modelos com tokenizers diferentes.

Uma última conferência custa um comando. Carregue o arquivo quantizado no `llama-completion` ou no `llama-server` e leia as primeiras respostas a olho nu antes de confiar em qualquer número, porque um arquivo pode pontuar bem e ainda assim falhar no seu template ou no seu idioma. Use o chat template que você vai servir. Uma calibração feita com texto simples diz pouco sobre tokens especiais.

## O erro clássico

O erro fácil é calibrar e pontuar no mesmo arquivo. A matriz parece então melhor do que é, porque foi ajustada àquilo com que você a avalia. Mantenha os conjuntos disjuntos: a documentação para calibrar, o teste do Wikitext-2 para pontuar. O mesmo cuidado vale para o arquivo de logits. Ele cresce com o tamanho do vocabulário vezes os tokens pontuados, e o arquivo daqui chegou a 1,55 GB para 20 chunks curtos com um vocabulário de 151.936 linhas. Um conjunto de teste completo com um vocabulário grande exige disco de verdade, então planeje o volume antes de começar.

:::warning
Não publique uma quantização com base numa execução. Os valores ± acima são o erro de amostragem de 20 chunks num modelo pequeno. Repita em texto do seu próprio trabalho antes de confiar num ranking de receitas, incluindo esta tabela.
:::

:::caveat
O placar do README usa o Llama 3 8B numa GPU CUDA. Não leve esses números para o Qwen3.8-27B, nem estes. Uma receita é um procedimento; a tabela é um resultado sobre um único modelo de 0,6B.
:::

A ideia durável: a conversão preserva, a calibração orienta, a quantização gasta e a medição em texto separado julga. Cada passo tem uma recusa ou um número que você consegue ler, então nunca é preciso adivinhar. A seguir, a lição 13.3 serve o arquivo que você construiu.
