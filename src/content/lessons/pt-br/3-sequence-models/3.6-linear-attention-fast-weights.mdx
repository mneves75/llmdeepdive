Attention paga pela própria memória do jeito mais literal possível: guarda tudo. Esta aula pergunta se isso é necessário e mostra a resposta que hoje roda na maior parte do modelo deste curso.

## O que attention paga por guardar tudo

Para produzir o token $t$, uma camada de attention causal compara a query nova (um vetor que diz o que o token atual procura) com a key de cada posição anterior, e mistura seus values com pesos de softmax:

$$
o_t=\sum_{i=1}^{t}\frac{\exp(q_t^{\top}k_i)}{\sum_{j=1}^{t}\exp(q_t^{\top}k_j)}\,v_i.
$$

Conte o que esse passo custa de verdade. O plano ingênuo, o que todo decoder com attention segue, armazena os $t$ vetores passados de key e value e faz $t$ comparações de similaridade para o token novo. O token um custa uma comparação, o token mil custa mil, e o token $n$ custa $n$. Então o trabalho por token é $O(n)$ no comprimento do contexto (leia "da ordem de $n$": cresce em proporção a $n$), e as keys e values armazenadas crescem sem limite.

Esse depósito é o KV cache, e a [aula 7.2](/pt-br/lessons/7-inference-and-efficiency/7.2-the-kv-cache/) deriva seu preço para o modelo do curso: no Qwen3.8-27B, no contexto nativo de 262.144 tokens, as keys e values em cache das camadas de attention chegam a 16 GiB para uma única sequência. A camada retém cada registro passado de key e value e dá à query nova um caminho ponderado direto para cada um. Isso evita a compressão em estado fixo. Mas o softmax ainda forma uma mistura ponderada, então não garante a recuperação exata de um token armazenado arbitrário.

A [aula 3.2](/pt-br/lessons/3-sequence-models/3.2-rnns-vanishing-gradient/) mostrou o desenho oposto: uma rede recorrente (RNN) carrega um hidden state de tamanho fixo, paga o mesmo custo a cada passo e não armazena nada por token. A pergunta desta aula é se o jeito como a attention endereça o passado cabe dentro de um estado de tamanho fixo.

## Tirar a softmax transforma attention numa recorrência

Katharopoulos et al. (2020) perceberam que o obstáculo é o softmax. A exponencial $\exp(q^\top k)$ amarra cada query a cada key, então a soma precisa ser recalculada para cada query nova. Troque-a por um **feature map** $\phi$ (mapa de features), uma função que transforma um vetor numa lista de features não negativas, de modo que o peso da posição $i$ seja proporcional a $\phi(q_t)^{\top}\phi(k_i)$. Agora as multiplicações podem ser reagrupadas (elas são associativas), e a query sai de dentro das somas:

$$
o_t=\frac{\phi(q_t)^{\top}\sum_{i\le t}\phi(k_i)v_i^{\top}}{\phi(q_t)^{\top}\sum_{i\le t}\phi(k_i)}.
$$

Nenhuma das duas somas depende mais da query, então ambas podem ser mantidas como totais correntes, do jeito que um laço mantém uma soma acumulada. Defina um estado matricial e um normalizador:

$$
S_t=S_{t-1}+\phi(k_t)v_t^{\top},\qquad z_t=z_{t-1}+\phi(k_t),
$$

em que cada passo soma uma matriz, $\phi(k_t)v_t^{\top}$ (o ⊤ marca uma transposição, então isso é uma coluna vezes uma linha), a $S$. A saída é uma única leitura, $o_t=\dfrac{S_t^{\top}\phi(q_t)}{z_t^{\top}\phi(q_t)}$. Repare no que aconteceu: isso é uma recorrência. A mesma regra de atualização roda em toda posição, o estado tem tamanho fixo, e o trabalho por token é constante. É o projeto de RNN da aula 3.2, exceto que o hidden state agora é uma matriz $d\times d$ de associações key-para-value em vez de um vetor. O custo por token cai de $O(n)$ para $O(1)$ (constante, seja qual for o comprimento), e a memória, de ilimitada para constante.

:::insight
O estado $S_t$ não é um vetor-resumo. É uma matriz de pesos, escrita durante a inferência e lida por multiplicação, exatamente como os pesos comuns de uma camada. Por isso a literatura mais antiga chama a ideia de **fast weights** (pesos rápidos). Slow weights (pesos lentos) são aprendidos no treino e depois congelados. Fast weights são escritos token a token: um pequeno programa aprendido atualizando a própria memória enquanto lê.
:::

## Por que escritas puramente aditivas interferem

Eis o problema da atualização acima: ela só sabe somar. Grave o value $v_a$ sob uma key, depois grave um $v_b$ diferente sob uma key quase idêntica, e a leitura devolve uma mistura dos dois. A associação velha nunca é removida, e conforme milhares de escritas se empilham, a interferência cresce.

Um caso de brinquedo mostra isso. Use keys com duas features e values que são números únicos. Pegue a key com features (1, 0). Grave o value 3 sob ela: o estado passa a guardar 3 na linha da primeira feature. Depois, grave o value 5 sob a mesma key. A regra aditiva soma de novo, então essa linha passa a guardar 8, e o normalizador contou a key duas vezes, então guarda 2. Ler com essa key devolve 8 / 2 = 4: a média do velho com o novo, que não é nem o value gravado por último nem o anterior.

A linear attention inicial abriu mão da precisão da softmax attention desse jeito. Ela teve desempenho inferior ao da softmax attention em tarefas que exigiam recall exato, e por isso passou anos como a ideia "derrotada". A conclusão tentadora é que isso é fundamental: um estado de tamanho fixo não consegue esquecer seletivamente, então o borrão com perdas seria o preço inevitável do $O(1)$. Essa conclusão está errada, e o conserto estava havia décadas na teoria de memórias associativas: mude a escrita, não o tamanho.

## A delta rule: ler primeiro, depois escrever a correção

A **delta rule** (regra delta) torna a escrita corretora de erros. Antes de escrever, recupere o que o estado prevê para a key que chega, lendo do mesmo jeito que qualquer query é lida, $S_{t-1}^{\top}\phi(k_t)$. Depois escreva apenas a diferença:

$$
S_t=S_{t-1}+\beta_t\,\phi(k_t)\bigl(v_t-S_{t-1}^{\top}\phi(k_t)\bigr)^{\top},
$$

com $\beta_t\in(0,1)$ uma força de escrita aprendida. De volta ao caso de brinquedo. Antes da segunda escrita, o estado prevê 3 para a key. O erro é 5 − 3 = 2. No caso-limite de força de escrita 1 (o valor aprendido fica sempre abaixo de 1), o estado ganharia o erro inteiro e passaria a guardar 5. Com 0,5 ele ganha 1 e guarda 4, a meio caminho entre o valor velho e o novo. (A delta rule lê o estado diretamente, sem o normalizador.)

Em geral há dois casos. Se o estado já guarda $v_t$ para essa key, o erro é quase zero e o estado fica em paz. Se guarda algo desatualizado, a atualização usa esse erro para mudar o estado ao longo da direção da key que chega. É uma escrita corretora de erro, não uma sobrescrita exata: seu efeito depende de $\beta_t$, das features da key e da interferência de outras associações. Cada passo é um passo de gradient descent online (uma pequena atualização de aprendizado por exemplo que chega) sobre o erro de recuperação da própria memória, então o estado aprende enquanto o modelo roda.

DeltaNet é linear attention com essa escrita. Adicionar os gates de esquecimento aprendido da [aula 3.3](/pt-br/lessons/3-sequence-models/3.3-lstm-gru-gates/), um decay sobre $S_{t-1}$ para o estado também desbotar o que não importa mais, produz o Gated DeltaNet (Yang et al., 2024), que a [aula 4.15](/pt-br/lessons/4-transformer/4.15-gated-deltanet/) disseca por completo.

:::warning
O equívoco mais comum é achar que linear attention é só attention acelerada. Não é uma aceleração da mesma função; é outra classe de funções. Softmax attention retém registros de key e value por posição e oferece acesso ponderado direto a eles. Linear attention comprime todo o passado num estado fixo com perdas, e nenhuma regra de escrita torna essa compressão exata. A delta rule administra bem a perda; ela não a elimina.
:::

## Por que o modelo do curso mantém os dois

É essa diferença que fez a ideia derrotada de 2020 virar arquitetura de produção em 2026. O Qwen3.8-27B, o espécime deste curso, constrói 48 das suas 64 camadas como Gated DeltaNet e mantém softmax attention completa em apenas 16, uma a cada quatro (Qwen3.8-27B Model Card, 2026). No caminho float32 de referência atual do Transformers, o estado recorrente de cada camada DeltaNet ocupa cerca de 3 MiB. Nas 48 camadas, isso dá algo em torno de 144 MiB, constante tenha a sequência cem tokens ou 262.144. O KV cache das camadas de attention, por outro lado, chega a 16 GiB no contexto completo.

O híbrido é uma admissão de engenharia de que os dois tipos de função são necessários. Memória fixa corretora de erros torna o comprimento barato. Umas poucas camadas com acesso a key e value por posição cuidam das buscas que a compressão em estado fixo não consegue representar de modo confiável. A RNN não perdeu para a attention afinal. Ela se retirou, aprendeu a escrever como uma memória e voltou como a maior parte do modelo.
