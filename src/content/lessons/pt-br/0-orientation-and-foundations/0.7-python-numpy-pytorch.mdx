## Python e NumPy: arrays e seus shapes

Python é a camada de coordenação do trabalho de machine learning. Você escreve variáveis, funções, loops e imports comuns, enquanto bibliotecas numéricas executam a aritmética pesada em **kernels**, rotinas compiladas de baixo nível. O hábito que mais importa é tornar o fluxo de dados explícito: nomeie seus shapes, evite estado global escondido, confira suposições nas fronteiras, e mantenha um experimento reprodutível enquanto ele ainda é pequeno o bastante para você raciocinar sobre ele.

O objeto central do NumPy é o array multidimensional. Duas operações que parecem semelhantes são inteiramente diferentes: `x * w` multiplica elemento a elemento, enquanto `x @ w` executa o produto matricial da [aula 0.5](/pt-br/lessons/0-orientation-and-foundations/0.5-matrix-multiplication-transformation/). Confundi-las produz um resultado com shape errado se você tiver sorte, e um resultado plausível com shape certo se não tiver. Inspecione `.shape` (o tamanho de cada eixo) e `.dtype` (o tipo numérico, como float de 32 bits) constantemente.

**Broadcasting** permite que um array menor atue sobre um maior sem loop. Some um array de shape `(3,)`, digamos `[10, 20, 30]`, a um de shape `(2, 3)`, e o NumPy soma `[10, 20, 30]` a cada uma das duas linhas. A regra: compare os shapes a partir da direita; duas dimensões combinam quando são iguais ou quando uma delas é 1, e uma dimensão ausente conta como 1. É assim que um vetor de bias, com um valor por feature, é somado a cada linha de um batch (uma pilha de exemplos processados juntos). Broadcasting é conveniente, e também é uma excelente forma de tirar média sobre um eixo que você pretendia manter sem que nenhum erro avise.

## PyTorch: devices, autograd e o loop de treinamento

Tensores do PyTorch oferecem as mesmas operações de array mais duas adições: devices e diferenciação automática.

- Um **device** é onde um tensor mora: a CPU ou uma GPU específica. Tensores em uma mesma operação em geral precisam de dtypes compatíveis e do mesmo device, e mover um modelo para uma GPU não arrasta junto todo objeto relacionado.
- O **autograd**, a diferenciação automática do PyTorch, registra operações sobre tensores que exigem gradientes. Quando você chama `backward` numa loss escalar, ele aplica a regra da cadeia da [aula 0.6](/pt-br/lessons/0-orientation-and-foundations/0.6-derivatives-gradients/) de trás para frente por esse grafo registrado.

O loop de treinamento tem um ritmo fixo: limpe os gradientes acumulados, rode o forward pass, reduza a uma loss escalar, chame `backward`, e então chame o `step` do otimizador. Aqui está um programa completo que roda essas quatro linhas numa CPU. Ele constrói os alvos a partir de uma regra conhecida e repete um passo de treinamento 100 vezes, até que um modelo linear de três features recupere essa regra. Salve-o como `train_step.py` e rode `uv run --with numpy --with torch python train_step.py` (ou instale `torch` e `numpy` com o pip e rode `python train_step.py`):

```python
import torch

torch.manual_seed(0)                          # os mesmos números aleatórios a cada execução
x = torch.randn(64, 3)                        # 64 exemplos, 3 features cada
true_w = torch.tensor([[2.0], [-1.0], [0.5]]) # a regra que o modelo precisa encontrar
y = x @ true_w + 0.1                          # alvos, shape (64, 1)

model = torch.nn.Linear(3, 1)                 # aprende um peso 3x1 e um bias
loss_fn = torch.nn.MSELoss()                  # erro quadrático médio
optimizer = torch.optim.SGD(model.parameters(), lr=0.1)

for step in range(100):
    optimizer.zero_grad()        # limpa os gradientes deixados pelo passo anterior
    loss = loss_fn(model(x), y)  # forward pass, reduzido a um número
    loss.backward()              # preenche o .grad de cada parâmetro
    optimizer.step()             # atualiza os parâmetros
    if step in (0, 99):
        print(f"step {step}: loss {loss.item():.4f}")

print("weight", [round(w, 2) for w in model.weight.flatten().tolist()])
print("bias", round(model.bias.item(), 2))
```

Com PyTorch 2.14.1, NumPy 2.5.4 e Python 3.13.11 numa CPU, ele imprimiu:

```text
step 0: loss 6.2754
step 99: loss 0.0000
weight [2.0, -1.0, 0.5]
bias 0.1
```

A loss do passo 0 depende dos pesos iniciais aleatórios, então outra versão do PyTorch pode imprimir outros dígitos ali. Os pesos e o bias recuperados ainda devem bater com a regra usada para construir os alvos.

Manter essas responsabilidades separadas é o que torna depurável um loop quebrado. `backward` computa gradientes e nunca muda parâmetros; `step` muda parâmetros e nunca computa gradientes.

## Módulos, avaliação e salvamento

Modelos maiores herdam de `torch.nn.Module` ou compõem módulos existentes; parâmetros registrados então aparecem em `model.parameters()`.

Note uma armadilha. `model.train()` e `model.eval()` alternam o comportamento de módulos como o dropout (que zera valores aleatoriamente durante o treinamento), mas não ligam nem desligam o rastreamento de gradientes. Avaliação sem derivadas precisa de `torch.no_grad`.

Para salvar um modelo, guarde um `state_dict` (um dicionário com seus tensores de parâmetros) mais configuração suficiente para reconstruí-lo. Serializar em vez disso um grafo de objetos opaco produz um arquivo que uma atualização de biblioteca pode se recusar a carregar.

## Lendo a configuração real do modelo

O que nos leva à configuração, e ao ponto central desta aula. Um modelo publicado é um par: pesos, e uma descrição do shape que esses pesos deveriam ter. A biblioteca `transformers` da Hugging Face lê o segundo sem baixar o primeiro, e é por isso que isso é barato o bastante para virar reflexo:

```python
from transformers import AutoConfig

config = AutoConfig.from_pretrained("Qwen/Qwen3.8-27B")
text = getattr(config, "text_config", config)

print(text.hidden_size)        # 5120
print(text.num_hidden_layers)  # 64
print(text.vocab_size)         # 248320
```

Três linhas de saída e você tem a espinha dorsal deste curso na mão:

- O 5120 é a largura do estado de um token, da [aula 0.4](/pt-br/lessons/0-orientation-and-foundations/0.4-vectors-matrices-dot-products/).
- O 64 é quantas vezes esse estado é reescrito.
- O 248.320 é quantos scores a camada final produz por posição, da [aula 0.1](/pt-br/lessons/0-orientation-and-foundations/0.1-what-is-a-language-model/).

O `getattr` na terceira linha está ali por um motivo. O Qwen3.8-27B é multimodal, então sua configuração carrega uma configuração de visão aninhada ao lado da de texto, e modelos multimodais diferentes colocam os campos de texto em profundidades diferentes. Escrever o fallback explicitamente faz o código declarar qual subconfiguração ele leu. Sem isso, você poderia pegar o hidden size de uma torre de visão e reportá-lo como se fosse o do modelo.

:::caveat
Ler um número não é o mesmo que entender o que ele conta. O valor 248.320 é o número de linhas de embedding. O tokenizer publicado mapeia 248.077 ids, deixando 243 linhas de tensor sem mapeamento. A divisibilidade por 512 é conveniente para hardware, mas os artefatos não documentam por que esse shape exato foi escolhido, que sinal essas linhas não mapeadas receberam nem como todo runtime as trata. Tome a configuração como autoridade sobre shapes de tensores e o tokenizer como autoridade sobre o mapeamento de texto para ids; a [aula 1.2](/pt-br/lessons/1-text-to-tensors/1.2-tokenization-i/) mostra por que confundi-los produz uma afirmação plausível e errada.
:::

## O que o autograd não pega por você

Reprodutibilidade exige mais do que uma semente aleatória. Registre versões de bibliotecas, divisões de dados, pré-processamento, hiperparâmetros, device, precisão e procedimento de avaliação, porque qualquer um deles pode mover um resultado mais do que a mudança que você está testando. Alguns kernels de acelerador continuam não determinísticos por design.

Mantenha sempre uma **baseline** simples, um método básico contra o qual comparar. Inspecione exemplos individuais em vez de apenas agregados, e assegure-se de que os shapes são os esperados e que as losses são finitas. Um loop de treinamento que roda verde até o fim pode otimizar o objetivo completamente errado com fidelidade perfeita.

:::warning
O equívoco mais comum entre quem está aprendendo essas bibliotecas é achar que o autograd valida o experimento. Ele não valida. O autograd garante que a derivada que ele reporta é a derivada da computação que você de fato executou, inclusive uma computação com um tensor transposto, um alvo mal rotulado, um conjunto de avaliação vazado, ou uma loss cuja média foi tirada no eixo errado. Ele é um motor de diferenciação, não um revisor.
:::

A habilidade portátil aqui não é decorar uma superfície de API que muda todo ano. É ler um programa de tensores como uma sequência de transformações de shape com estado explícito: o que cada eixo significa, quais valores exigem gradientes, onde entra a aleatoriedade, qual redução produz a loss, e quando os parâmetros mudam. Some a isso o reflexo de carregar a configuração real de um modelo em vez de citar um número de memória, e o resto do curso é uma questão de seguir shapes.
