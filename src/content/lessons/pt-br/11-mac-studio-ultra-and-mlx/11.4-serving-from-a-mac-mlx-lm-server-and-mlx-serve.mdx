Um Mac Studio em cima da mesa é um ótimo servidor de inferência para uma equipe, e dois programas o transformam em um. O `mlx_lm.server` vem com o mlx-lm, do projeto ml-explore da Apple. O `mlx-serve` é um projeto separado em Zig, de David Dalcu (um projeto sem relação, raspoli/mlx-serve, tem o mesmo nome; confira o dono), fixado aqui na v26.10.1. Os dois falam uma API no estilo OpenAI. Diferem no que agrupam em batch, no que guardam em cache e em quem consegue alcançá-los por padrão.

## O mlx_lm.server na 0.32.0

Inicie-o em loopback e depois consulte-o a partir de um segundo terminal:

```bash
mlx_lm.server --model mlx-community/Qwen3-4B-Instruct-2507-4bit --host 127.0.0.1 --port 8080
```

```bash
curl -s http://127.0.0.1:8080/health
curl -s http://127.0.0.1:8080/v1/chat/completions -H 'Content-Type: application/json' -d '{"messages":[{"role":"system","content":"You are a terse assistant for the fictional Harbor service. Retry budget is three attempts. Delay starts at 200 ms and doubles."},{"role":"user","content":"How many attempts?"}],"max_tokens":24,"temperature":0}'
```

Os endpoints são `/v1/chat/completions` (também `/chat/completions`), `/v1/completions`, `/v1/models` e `/health`. Rode o pedido de chat duas vezes. A primeira resposta traz `"cached_tokens": 0` em `usage.prompt_tokens_details`. A segunda repete o prompt e informa 44 dos seus 45 tokens em cache. Esse campo é como você enxerga o reaproveitamento de prompt de fora. Por dentro, um LRU de caches distintos (10 por padrão, com teto em bytes dado por `--prompt-cache-bytes`) é consultado atrás do prefixo de tokens em cache mais próximo.

O batching vem ligado por padrão, com `--decode-concurrency 32` e `--prompt-concurrency 8`. Um pedido só entra em batch se o servidor não tem modelo de rascunho, todo tipo de cache sabe fazer merge, o pedido não define `seed` e `--kv-bits` não está definido. Caso contrário, o servidor esvazia o batch e atende o pedido sozinho. A quantização de KV da lição 11.3 portanto troca batching por memória: nesta versão, um servidor iniciado com `--kv-bits` trata um pedido por vez.

## O mlx-serve v26.10.1

O mlx-serve é um único binário nativo que serve modelos MLX e, por meio de um llama.cpp embutido, arquivos GGUF. Ele fala os formatos OpenAI, Anthropic e Ollama numa só porta. Seu `LICENSE` é MIT para o código próprio, com componentes de terceiros sob termos próprios. Baixe a release, confira o hash contra o digest que o GitHub mostra e inicie em loopback:

```bash
gh release download v26.10.1 --repo ddalcu/mlx-serve --pattern 'mlx-serve-bin-macos-arm64.tar.gz'
shasum -a 256 mlx-serve-bin-macos-arm64.tar.gz
tar -xzf mlx-serve-bin-macos-arm64.tar.gz
./mlx-serve-macos-arm64/mlx-serve --version
./mlx-serve-macos-arm64/mlx-serve --model q4-g64 --serve --host 127.0.0.1 --port 11234 --max-concurrent 4
```

Num segundo terminal, peça uma resposta no estilo Anthropic:

```bash
curl -s http://127.0.0.1:11234/v1/messages -H 'Content-Type: application/json' -H 'anthropic-version: 2023-06-01' -d '{"model":"mlx-serve","max_tokens":16,"messages":[{"role":"user","content":"Name one planet."}]}'
```

A linha de `--version` informa o MLX embutido, 0.32.3 nesta release. O diretório `q4-g64` é o modelo MLX que a lição 11.3 converteu. O continuous batching fica desligado até você passar `--max-concurrent N`, e o prefix cache vem ligado por padrão. As respostas dele acrescentam um objeto `timings`, que é o relógio do próprio servidor.

## A virada errada clássica

A virada errada é comparar dois servidores por um número vindo de dois relógios diferentes. O tempo até o primeiro token não é o primeiro byte. O `mlx_lm.server` escreve linhas de comentário SSE como `: keepalive 10/11` enquanto processa o prompt, e os dois servidores enviaram bytes antes de qualquer texto. Meça no cliente e pare o relógio no primeiro chunk que traz texto:

```python
import json, sys, time, urllib.request

def measure(base, prompt, max_tokens=64):
    body = json.dumps({
        "messages": [{"role": "user", "content": prompt}],
        "max_tokens": max_tokens, "temperature": 0, "stream": True,
        "stream_options": {"include_usage": True},
    }).encode()
    req = urllib.request.Request(base + "/v1/chat/completions", body,
                                 {"Content-Type": "application/json"})
    t0 = time.perf_counter()
    first_byte = first_text = last_text = usage = None
    with urllib.request.urlopen(req) as resp:
        for raw in resp:
            now = time.perf_counter() - t0
            first_byte = now if first_byte is None else first_byte
            line = raw.decode().strip()
            if not line.startswith("data: ") or line == "data: [DONE]":
                continue
            chunk = json.loads(line[6:])
            usage = chunk.get("usage") or usage
            for choice in chunk.get("choices", []):
                if choice.get("delta", {}).get("content"):
                    first_text = now if first_text is None else first_text
                    last_text = now
    n = usage["completion_tokens"]
    return {"first_byte_s": first_byte, "ttft_s": first_text,
            "decode_tok_s": (n - 1) / (last_text - first_text),
            "cached": usage.get("prompt_tokens_details", {}).get("cached_tokens")}

print(measure(sys.argv[1], sys.argv[2]))
```

Rode `python ttft.py http://127.0.0.1:8080 "Write two sentences about harbors."` contra cada servidor. A taxa de decode conta os tokens depois do primeiro, a partir do bloco usage, sobre o tempo entre o primeiro e o último texto. Para uma comparação justa, use os mesmos pesos e o mesmo prompt com temperature 0, registre `cached` para manter separadas as execuções frias e quentes, repita e relate a dispersão, e iguale os ajustes que mudam o trabalho. Isso quer dizer `--decode-concurrency` contra `--max-concurrent`, e o speculative decoding do mlx-serve, já que o Prompt Lookup Decoding vem ligado por padrão e `--no-pld` o desliga. Não cite números de outro Mac nem de outro modelo.

:::warning
Nenhum dos dois servidores é um serviço de internet endurecido. O `mlx_lm.server` documenta que implementa apenas verificações básicas de segurança. Ele não tem autenticação, `--allowed-origins` vem como `*` por padrão, e o campo `model` de um pedido pode nomear outro modelo para o servidor carregar. O mlx-serve usa `0.0.0.0` por padrão, no texto de ajuda e no `main.zig`, embora o seu `SECURITY.md` diga que 127.0.0.1 é o padrão. O `--api-key` dele isenta o loopback, a menos que você acrescente `--api-key-strict`, e o `--lan-share` anuncia modelos por Bonjour. Passe sempre `--host 127.0.0.1` e ponha um proxy de verdade, com autenticação, na frente de qualquer coisa compartilhada.
:::

:::caveat
A tabela do README do mlx-serve lista o mlx-lm como sem API compatível com OpenAI e sem continuous batching. O código-fonte fixado do mlx-lm tem as duas coisas. Leia o código-fonte fixado, não uma tabela de comparação, a desta lição inclusive. As afirmações de throughput daquele README não foram reproduzidas aqui. Os servidores rodaram apenas para confirmar os comandos e os formatos de resposta acima.
:::

A ideia durável é que servir acrescenta três perguntas à inferência: quem pode se conectar, o que é agrupado ou guardado em cache e em qual relógio você confia. A lição 11.5 pergunta o que muda quando um Mac não basta.
