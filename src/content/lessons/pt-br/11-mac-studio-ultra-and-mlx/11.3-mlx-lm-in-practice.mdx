A lição 8.9 mostrou um comando de conversão. Esta lição acompanha um checkpoint por todo o caminho do mlx-lm (converter, conferir, ajustar, fazer o fuse, guardar em cache) na versão 0.32.0, e marca as junções em que uma ferramenta refaz trabalho em silêncio. Todos os comandos abaixo rodaram no mlx-lm 0.32.0 com MLX 0.32.3, usando um Qwen3 de 4B em 4 bits, que estava em cache, no lugar do modelo do curso. Um substituto de 4B confere o procedimento, não a qualidade nem a velocidade do 27B.

## Converta e leia os bits por peso

O `mlx_lm.convert` aceita `-q` para quantizar, `--q-bits`, `--q-group-size`, `--q-mode` (`affine`, `mxfp4`, `nvfp4` ou `mxfp8`), `--dtype` para os tensores não quantizados e `-d` para desquantizar. Se você omitir bits e tamanho de grupo, os padrões dependem do modo: `affine` usa 4 bits com grupo de 64, `mxfp4` 4 bits com grupo de 32, `nvfp4` 4 bits com grupo de 16 e `mxfp8` 8 bits com grupo de 32. Uma camada cuja última dimensão não é múltipla do tamanho do grupo é pulada e fica sem quantizar. As receitas de `--quant-predicate`, `mixed_2_6`, `mixed_3_4`, `mixed_3_6` e `mixed_4_6`, mantêm o `lm_head` e partes de `v_proj` e `down_proj` na largura maior. Elas valem só para `affine`.

O substituto já está em 4 bits; então o primeiro comando o desquantiza numa fonte de 16 bits. Conversões de verdade partem do checkpoint original, e esse vaivém serve apenas para rodar todas as flags:

```bash
mlx_lm.convert --hf-path mlx-community/Qwen3-4B-Instruct-2507-4bit -d --mlx-path src16
mlx_lm.convert --hf-path src16 -q --q-bits 4 --q-group-size 64 --mlx-path q4-g64
mlx_lm.convert --hf-path src16 -q --q-bits 4 --q-group-size 32 --mlx-path q4-g32
mlx_lm.convert --hf-path src16 -q --quant-predicate mixed_4_6 --mlx-path q-mixed46
mlx_lm.convert --hf-path src16 -q --q-mode mxfp4 --mlx-path q-mxfp4
```

Cada execução termina com uma linha como `Quantized model with 4.501 bits per weight`. Neste modelo de 4B, as quatro execuções imprimiram 4,501, 5,001, 4,747 e 4,251. O modo affine guarda uma escala e um bias por grupo, no dtype da entrada; então, num modelo de 16 bits, um código de 4 bits custa cerca de $4 + 32/g$ bits: 4,5 com $g = 64$ e 5,0 com $g = 32$. O modo `mxfp4` guarda uma escala de 8 bits para cada 32 elementos e nenhum bias, o que dá $4 + 8/32 = 4.25$. A regra da lição 7.9 vale aqui também: os bits efetivos superam a largura nominal; portanto leia o número impresso e compare os tamanhos de arquivo. Os métodos aprendidos (`mlx_lm.dwq`, `awq`, `dynamic_quant`, `gptq`) refinam isso, e o guia nas citações os cobre. Esta lição não os executou.

## Confira e depois ajuste

Uma quantização precisa de uma conferência em texto separado. O `mlx_lm.perplexity` avalia um modelo num dataset do Hugging Face ou numa pasta local no formato do mlx-lm, e precisa do pacote `datasets` (`pip install "mlx-lm[train]"`). O `mlx_lm.lora` lê `train.jsonl`, um `valid.jsonl` opcional e `test.jsonl`, nos formatos `chat`, `completions`, `tools` ou `text`. Quando o `--model` é quantizado, o treino é QLoRA. Monte um conjunto minúsculo e ajuste com ele:

```python
import json, os

os.makedirs("data", exist_ok=True)
rows = [
    {"messages": [
        {"role": "user", "content": f"Reply with the ticket tag for item {i}."},
        {"role": "assistant", "content": f"TICKET-{i:03d}"},
    ]}
    for i in range(1, 25)
]
for name, part in [("train", rows[:20]), ("valid", rows[20:22]), ("test", rows[22:])]:
    with open(f"data/{name}.jsonl", "w") as f:
        f.writelines(json.dumps(r) + "\n" for r in part)
```

```bash
mlx_lm.perplexity --model q4-g64 --data-path data --num-samples 2 --sequence-length 64 --batch-size 1
mlx_lm.lora --model mlx-community/Qwen3-4B-Instruct-2507-4bit --train --data data \
  --iters 30 --batch-size 1 --num-layers 4 --mask-prompt --grad-checkpoint \
  --adapter-path adapters --test
```

O `--mask-prompt` calcula a loss só na completion. `--num-layers` (padrão 16), `--batch-size`, `--grad-accumulation-steps` e `--grad-checkpoint` são as alavancas de memória do `LORA.md`. A configuração do adapter registra rank 8, escala 20, sem dropout e learning rate de 1e-5. O ajuste também funcionou numa versão Qwen3.5 de 9B, da família de arquitetura do modelo do curso.

## A virada errada clássica: fazer o fuse numa base quantizada

O `mlx_lm.fuse` incorpora o adapter aos pesos. Em `tuner/lora.py`, uma camada quantizada é desquantizada, o delta é somado e a soma é quantizada de novo. Um delta pequeno pode desaparecer nesse novo arredondamento. O `--dequantize` mantém 16 bits. Faça o fuse dos dois jeitos e compare os logits com a base mais o adapter:

```bash
mlx_lm.fuse --model mlx-community/Qwen3-4B-Instruct-2507-4bit --adapter-path adapters --save-path fused-q
mlx_lm.fuse --model mlx-community/Qwen3-4B-Instruct-2507-4bit --adapter-path adapters --save-path fused-16 --dequantize
```

```python
import mlx.core as mx
from mlx_lm import load

base = "mlx-community/Qwen3-4B-Instruct-2507-4bit"
prompt = "Reply with the ticket tag for item 7."

def last_logits(path, **kw):
    model, tok = load(path, **kw)
    ids = tok.apply_chat_template([{"role": "user", "content": prompt}], add_generation_prompt=True)
    out = model(mx.array(ids)[None])[:, -1, :].astype(mx.float32)
    mx.eval(out)
    return out

plain = last_logits(base)
ref = last_logits(base, adapter_path="adapters")
print("adapter vs base:", round(mx.abs(ref - plain).max().item(), 2))
for name in ("fused-q", "fused-16"):
    got = last_logits(name)
    print(name, "gap:", round(mx.abs(got - ref).max().item(), 2),
          "top token = adapter's:", got.argmax().item() == ref.argmax().item(),
          "= base's:", got.argmax().item() == plain.argmax().item())
```

Nesta execução de brinquedo (30 passos), o adapter moveu os logits em até cerca de 29. O fuse em 4 bits ficou a cerca de 23 da base mais o adapter, e seu token de maior probabilidade voltou a ser o do modelo base. O fuse em 16 bits ficou a 0,25 e manteve o token do adapter. Os valores mudam um pouco de uma execução para outra, e o adapter era fraco demais para ser útil; por isso eles não provam nada sobre qualidade. Mostram que a conferência pega a junção. Quantizar o fuse de 16 bits não ajudou neste substituto: a distância foi 25,62 e o token de maior probabilidade voltou ao do modelo base. Um adapter fraco não sobrevive ao arredondamento de 4 bits de nenhum dos dois jeitos. Mantenha o fuse de 16 bits, ou mantenha o adapter separado e carregue-o com `--adapter-path`. Avalie qualquer exportação em 4 bits como qualquer outra quantização.

## Prompt cache e flags de KV cache

O `mlx_lm.cache_prompt` salva o prefill de um prefixo compartilhado, e o `mlx_lm.generate --prompt-cache-file` o trata como prefixo do prompt novo (e lê o modelo a partir do arquivo):

```bash
printf 'Release notes for the fictional Harbor service. Version 4 adds a retry budget of three attempts per request. The retry delay doubles after each failure.\n' > doc.txt
mlx_lm.cache_prompt --model mlx-community/Qwen3-4B-Instruct-2507-4bit --prompt - --prompt-cache-file harbor.safetensors < doc.txt
mlx_lm.generate --prompt-cache-file harbor.safetensors --prompt "How many attempts does the retry budget allow?" --max-tokens 40
mlx_lm.generate --model mlx-community/Qwen3-4B-Instruct-2507-4bit --prompt "Name one planet." --max-tokens 20 --kv-bits 4 --quantized-kv-start 0
```

O `--max-kv-size n` troca o cache por um cache rotativo que mantém os quatro primeiros tokens e a janela mais recente. O `--kv-bits` quantiza o cache com `--kv-group-size` (padrão 64), a partir de `--quantized-kv-start`, que tem como padrão 5.000 tokens. Um teste curto com o início padrão não mostra efeito algum, e é por isso que o último comando o define como 0.

:::warning
As duas flags de cache não se combinam e nem sempre se aplicam. No substituto denso, `--kv-bits` com `--max-kv-size` para com `NotImplementedError: RotatingKVCache Quantization NYI`. Numa versão Qwen3.5 de 9B, cujo `model_type` o modelo do curso compartilha, o `make_prompt_cache` devolve o cache do próprio modelo, 24 camadas DeltaNet com `ArraysCache` e 8 camadas de attention com `KVCache`, seja qual for o `--max-kv-size`. Só as camadas de attention podem ser quantizadas. O estado DeltaNet não é um KV cache; então a economia no 27B vale apenas para as suas 16 camadas de attention. Além disso, o arquivo `SERVER.md` avisa que o attention sobre um cache quantizado mantém uma matriz de scores do tamanho do passo de prefill por tamanho do contexto; portanto reduza o `--prefill-step-size` ao quantizar.
:::

:::caveat
O `LORA.md` lista famílias de modelos anteriores às camadas híbridas; portanto rode a sua arquitetura antes de planejar um job de ajuste.
:::

A ideia durável é que cada comando do mlx-lm é barato e silencioso, então as conferências entre eles carregam a qualidade. A lição 11.4 coloca o resultado atrás de uma API HTTP.
