Algumas interfaces não têm árvore de acessibilidade que valha a leitura: uma área de trabalho remota, um canvas, uma página legada feita de imagens. Ali o agente vê só uma captura de tela, e um modelo de visão responde em pixels: "clique em (547; 422)". O navegador do exercício roda com *fator de escala do dispositivo* 2, a razão entre pixels físicos da tela e pixels CSS numa tela de alta densidade. A viewport, a área visível da página, tem 800 por 600 pixels CSS, então a captura tem 1600 por 1200. O botão de exportação de março tem centro em (273,5; 211) na viewport, que é (547; 422) na captura. Passe os números do modelo direto para o mouse e o clique cai em (547; 422) na viewport, à direita de todos os botões, em nada.

A resposta do modelo não tinha nada de errado. O controlador misturou dois espaços de coordenadas.

## Três espaços de coordenadas

Três espaços se encontram num clique.

- *Pixels da imagem*: posições na figura que o modelo viu, com (0, 0) no canto superior esquerdo.
- *Pixels do dispositivo*: os pixels físicos da tela. A captura do Playwright usa `scale="device"` por padrão, que a API descreve como "a single pixel per each device pixel, so screenshots of high-dpi devices will be twice as large or even larger", um pixel por pixel do dispositivo, de modo que capturas de telas de alta densidade ficam duas vezes maiores ou mais.
- *Pixels CSS relativos à viewport*: as unidades em que uma página web se organiza, medidas a partir do canto superior esquerdo da área visível. A classe `Mouse` do Playwright "operates in main-frame CSS pixels relative to the top-left corner of the viewport", opera em pixels CSS do quadro principal relativos ao canto superior esquerdo da viewport, e os boxes de um aria snapshot usam as mesmas unidades.

Um provedor de modelos pode acrescentar mais uma etapa. A documentação da Anthropic para seus modelos de visão, lida em 2026-10-18, diz que as coordenadas que seu modelo devolve "are pixel positions in the image Claude sees", são posições na imagem que o modelo vê, depois que o serviço reduziu uma imagem grande demais. O exemplo dela reduz uma captura de 1920 por 1080 para 1456 por 819. Essa página descreve o serviço de um provedor; os testes do curso não o chamam, e outros provedores redimensionam de outro jeito ou não redimensionam.

A saída é registrar o tamanho da imagem que o modelo de fato recebeu. Então uma razão por eixo, a largura da viewport dividida pela largura da imagem, cobre ao mesmo tempo o fator de escala do dispositivo e qualquer redução. Com $r$ essa razão, $s^{\text{capture}}$ o deslocamento de rolagem quando a captura foi feita e $s^{\text{now}}$ o deslocamento na hora do clique:

$$
x_{\text{view}} = s_x^{\text{capture}} + r\,x_{\text{img}} - s_x^{\text{now}}
$$

e o mesmo para $y$. No caso do início, $r = 800 / 1600 = 0.5$ e nada rolou, então (547; 422) vira (273,5; 211).

## Rolagem e referenciais velhos

Um *referencial* (*frame*) aqui é uma observação: a captura mais a geometria necessária para agir sobre ela depois. Entre a captura e o clique a página pode se mover. No exercício a viewport tem 320 pixels de altura, o modelo aponta para o botão de março, e então a página rola 60 pixels. Clicar no ponto convertido sem a correção de rolagem cai no botão de abril, uma linha abaixo. É um clique válido no relatório errado. A transformação guarda no referencial a rolagem da captura e subtrai a atual:

```python
# file: examples/agent-engineering/src/agentlab/gui/coordinates.py
def image_to_viewport(x: float, y: float, frame: Frame, *, scroll_x: float | None = None, scroll_y: float | None = None) -> tuple[float, float]:
    """Map an image pixel to viewport CSS pixels at the page's current scroll position."""
    if not (0 <= x <= frame.image_width and 0 <= y <= frame.image_height):
        raise OffscreenTarget(f"({x}, {y}) is outside the {frame.image_width}x{frame.image_height} image")
    ratio = frame.ratio()
    now_x = frame.scroll_x if scroll_x is None else scroll_x
    now_y = frame.scroll_y if scroll_y is None else scroll_y
    # Page point = where the frame started + offset inside it; the viewport starts at the current scroll.
    view_x = frame.scroll_x + x * ratio - now_x
    view_y = frame.scroll_y + y * ratio - now_y
    if not (0 <= view_x <= frame.viewport_width and 0 <= view_y <= frame.viewport_height):
        raise OffscreenTarget(f"the target is at ({view_x}, {view_y}), outside the viewport after scrolling")
    return (view_x, view_y)
```

`frame.ratio()` lança um erro se os dois eixos discordarem em mais de 1%, porque aí a imagem foi recortada ou preenchida, não redimensionada, e uma razão única estaria errada. Um ponto que rolou para fora da vista lança `OffscreenTarget`, que significa "tire uma captura nova", nunca "clique assim mesmo".

## Set-of-Mark: deixe o modelo nomear uma marca

Estimar pixels é a etapa fraca. O prompting com Set-of-Mark (Yang e colegas, 2023) tira essa etapa do modelo. O artigo divide uma imagem em regiões com modelos de segmentação prontos (SEEM e SAM), desenha um rótulo em cada região (números, letras, máscaras ou caixas) e deixa o GPT-4V responder com um rótulo. Os autores relatam que, sem exemplos (*zero-shot*), isso superou o melhor modelo totalmente ajustado (*fine-tuned*) num benchmark de expressões referenciais. Esse resultado é sobre as tarefas do artigo; não é uma medição de agentes de navegador.

O exercício mantém a ideia e muda a origem das regiões. Num navegador, a árvore de acessibilidade já conhece cada elemento interativo e seu box: `aria_snapshot(mode="ai", boxes=True)` do Playwright lista cada um com uma referência como `e16` e seu box na viewport. `parse_marks` fica com os interativos, `draw_marks` pinta cada referência na página para a captura, e o modelo pode responder "e16". Os rótulos ficam escondidos da árvore de acessibilidade e deixam os cliques passarem, o que um teste confere. O Playwright em si não implementa Set-of-Mark. O snapshot dele é só uma fonte conveniente de regiões.

## Confira o que está sob o ponto antes de clicar

Tenha o modelo respondido com um rótulo ou com pixels, o controlador confirma o alvo logo antes de agir:

```python
# file: examples/agent-engineering/src/agentlab/gui/marks.py
def pick_mark(x: float, y: float, marks: list[Mark]) -> Mark | None:
    """The one mark under a point, or None when no mark or several marks contain it.

    None means "observe again", never "click anyway": a point on two targets
    is a guess between them.
    """
    under = [mark for mark in marks if mark.contains(x, y)]
    return under[0] if len(under) == 1 else None
```

`click_point`, em `browser.py`, converte o ponto com a rolagem atual, tira um snapshot novo e só clica se `pick_mark` encontrar exatamente um elemento ali. Caso contrário, registra um evento `gui.reobserve` e devolve `None` sem tocar no mouse. Numa área de trabalho remota sem árvore, a única verificação possível é outra captura, que é mais fraca: mostra o que está ali, não o que aquilo é. Esse é mais um motivo para a [aula 18.1](/pt-br/lessons/18-computer-use-and-gui-automation/18.1-observe-before-acting/) preferir o caminho semântico sempre que a página o oferece.
