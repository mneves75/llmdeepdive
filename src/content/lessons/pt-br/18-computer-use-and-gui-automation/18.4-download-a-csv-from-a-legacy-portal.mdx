A execução aperta "Download April 2026 CSV". Na mesma hora aparece um aviso: "Export complete. Your download has started." Uma execução que confia na página relata sucesso e segue. Nenhum arquivo chegou. O servidor do portal respondeu com um erro, e o aviso tinha sido escrito pelo próprio script da página no instante do clique, antes de o servidor dizer qualquer coisa.

Esta aula transforma "o download funcionou" em verificações que um programa consegue rodar.

## O que "o download funcionou" precisa significar

Para o assistente de compras, um download terminado significa que tudo isto vale:

1. Um download começou de fato dentro de um prazo.
2. Ele veio da própria origem do portal.
3. Foi salvo dentro da pasta da execução, com um nome que o controlador aceitou.
4. O arquivo é texto CSV, não uma página HTML com nome `.csv`.
5. As colunas são exatamente as colunas do relatório.
6. Cada linha pertence ao período pedido e tem valores razoáveis.

O portal do exercício falha em cada uma delas de propósito. Março é a única exportação boa. Abril falha no servidor, maio manda uma página HTML de erro como `report-2026-05.csv`, junho manda um arquivo bem formado com as linhas de março, e julho dá ao arquivo o nome `../../report-2026-07.csv`. Toda exportação também chega 400 milissegundos depois de o aviso afirmar que ela começou.

## Esperar pelo arquivo, não pelo aviso

O Playwright informa um download como um evento. `page.expect_download()` espera por ele enquanto o clique roda, e desiste com um erro de timeout depois de um prazo. A documentação acrescenta dois fatos que moldam o código: "All these attachments are downloaded into a temporary folder", todos esses anexos são baixados para uma pasta temporária, e "Downloaded files are deleted when the browser context that produced them is closed", os arquivos baixados são apagados quando o contexto de navegador que os produziu é fechado. Então o controlador precisa copiar o arquivo para um lugar seu antes de a execução terminar. `Download.failure()` "returns download error if any", devolve o erro do download, se houver, e espera o download terminar antes.

```python
# file: examples/agent-engineering/src/agentlab/gui/browser.py
    try:
        with page.expect_download(timeout=timeout_ms) as started:
            press()
    except PlaywrightTimeout:
        banner = page.get_by_role("status").first.inner_text()
        trace.record("gui.download", ok=False, banner=banner)
        return Outcome("failed", f"no download started within {timeout_ms:.0f} ms, although the page says {banner!r}")
```

`press` é o que dispara a exportação: um clique semântico, ou um clique por coordenadas. Quando nada chega, o resultado cita o aviso, então o trace guarda a contradição para quem o ler depois. O atraso de 400 milissegundos é o motivo de o código esperar pelo evento: uma execução que conferisse a pasta logo depois do clique a encontraria vazia até para março.

Por que não esperar um tempo fixo? Uma pausa longa o bastante para a exportação mais lenta desperdiça esse tempo em todas as rápidas, e uma pausa ajustada à velocidade de hoje falha no dia em que o servidor estiver lento. Esperar pelo evento termina assim que o arquivo começa, e o prazo diz quanto tempo a execução aceita esperar antes de relatar uma falha. Os testes usam 3.000 ms para exportações que devem funcionar e 1.500 ms para a de abril, que nunca vai funcionar.

## O nome vem do servidor

O nome do arquivo chega no cabeçalho `Content-Disposition` da resposta, escrito pelo servidor. A RFC 6266 manda tratá-lo "as advisory only", só como sugestão, e diz que "Recipients MUST NOT be able to write into any location other than one to which they are specifically entitled", quem recebe não pode conseguir escrever em nenhum lugar além daquele a que tem direito. Uma estratégia que ela menciona é ficar só com o último segmento do caminho. O exercício é mais rígido e recusa o nome, porque um portal que manda `../../report-2026-07.csv` está se comportando mal:

```python
# file: examples/agent-engineering/src/agentlab/gui/report.py
def safe_destination(folder: Path, suggested_name: str) -> Path:
    """Where to save a download. The name comes from the server's header, so it is untrusted input."""
    if not CSV_NAME.match(suggested_name):
        raise ReportRejected(f"refusing file name {suggested_name!r}")
    target = (folder / suggested_name).resolve()
    if target.parent != folder.resolve():
        raise ReportRejected(f"{suggested_name!r} would land outside {folder}")
    if target.exists():
        raise ReportRejected(f"{target.name} already exists; a download never overwrites a file")
    return target
```

`CSV_NAME` aceita letras, dígitos, pontos, hífens e sublinhados, terminando em `.csv`, então barras nunca chegam à verificação do caminho. A comparação com `resolve()` é uma segunda barreira, independente. Um download também nunca sobrescreve um arquivo anterior, que poderia ser um relatório que alguém já conferiu.

## Conferir o que o arquivo contém

Só agora o controlador olha dentro. `validate_report` lê os bytes e recusa, com um motivo, qualquer coisa que não seja o relatório pedido:

```python
# file: examples/agent-engineering/src/agentlab/gui/report.py
    if raw.lstrip()[:1] == b"<":
        raise ReportRejected("the file is HTML, not CSV (an error or login page saved under a .csv name)")
    try:
        text = raw.decode("utf-8")
    except UnicodeDecodeError as error:
        raise ReportRejected("the file is not UTF-8 text") from error
    reader = csv.DictReader(io.StringIO(text, newline=""))
    if tuple(reader.fieldnames or ()) != REPORT_COLUMNS:
        raise ReportRejected(f"unexpected columns {reader.fieldnames}")
```

Depois das colunas, cada linha precisa trazer o período pedido, um identificador de pedido de compra no formato `PO-` mais quatro dígitos, uma quantidade positiva e um preço unitário positivo. Se qualquer verificação falha, `download_report` apaga a cópia salva, para que um arquivo recusado nunca seja confundido com um resultado depois. Para março, as linhas aceitas são exatamente os quatro registros de compra do tenant-a nas fixtures do projeto, o que um teste compara.

:::insight
`failure()` e essas verificações respondem a perguntas diferentes. `failure()` diz se os bytes chegaram. As verificações dizem se os bytes são o relatório. A página de erro de maio chega inteira, então `failure()` devolve `None`, e só ler o arquivo mostra que é HTML.
:::

## Modo captura de tela, mesmas verificações

A trilha mantém um exercício só com capturas de tela, do jeito que um agente trabalha numa área de trabalho remota. Um modelo de visão roteirizado responde com um pixel da imagem numa captura em escala de dispositivo, `click_point`, da [aula 18.2](/pt-br/lessons/18-computer-use-and-gui-automation/18.2-pixels-coordinates-and-set-of-mark/), converte e clica, e o mesmo `download_report` decide se a execução terminou. O caminho por visão muda como o clique acontece, nunca o que conta como terminado.

## Rode o exercício

A partir de `examples/agent-engineering/`, rode as verificações principais com `uv run --frozen python -m unittest discover -s tests -p "test_gui_report.py"`; a saída termina com `Ran 12 tests` e `OK`. Os testes de navegador rodam com `uv run --frozen python -m unittest discover -s tests_browser -p "test_gui_download.py"` e terminam com `Ran 5 tests` e `OK`. Cada teste baixa para uma pasta temporária nova, que é removida no fim.

`test_the_delayed_march_export_matches_the_fixture` espera o atraso e compara as linhas com a fixture. `test_a_failed_export_is_caught_although_the_banner_says_complete` confere tanto o resultado falho quanto o texto do aviso. `test_an_html_page_named_csv_is_refused_and_removed` e `test_a_file_name_that_climbs_out_of_the_folder_is_refused` conferem que nada fica na pasta nem cai acima dela. `test_screenshot_only_the_same_checks_apply` baixa março por coordenadas.

Para ver duas verificações se sobreporem, apague a verificação de HTML em `validate_report`. `test_an_html_page_saved_as_csv_is_refused` fica vermelho, mas o arquivo continua recusado, agora pela verificação de colunas e com um motivo menos útil. O teste fixa qual verificação nomeia o problema. Restaure a linha.
