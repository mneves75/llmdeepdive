O script de relatório soma um CSV e escreve um arquivo JSON. Ele não precisa de rede nenhuma. Agora suponha que a mensagem do fornecedor guiou o modelo e que o script ganhou duas linhas. Uma manda o CSV inteiro para um servidor do atacante. A outra pede a `http://169.254.169.254/latest/meta-data/` as credenciais de nuvem da máquina. As duas são *egress*, tráfego saindo da sandbox, e as duas dão certo no subprocesso da [aula 17.2](/pt-br/lessons/17-sandboxed-agent-execution/17.2-resource-and-filesystem-limits/), que divide a rede do host. Esta aula decide quais conexões um convidado pode fazer, explica por que a decisão precisa ser sobre endereços e não sobre nomes, e mantém os segredos do controlador fora do alcance do convidado.

## Para onde os pacotes do convidado podem ir?

O padrão seguro é *negar por padrão* (*default deny*): nenhum destino é permitido a menos que uma regra o nomeie. Para o script de relatório, a lista de regras é vazia. Um convidado que precisa de uma API de fornecedor ganha exatamente um par `(host, porta)`.

Três detalhes decidem se "negar" nega de verdade:

- **DNS é saída.** Resolver um nome manda uma consulta a um resolvedor, e o próprio nome pode levar dados para fora (`<dados-roubados>.attacker.example`). Um convidado sem rede também não deve resolver nomes.
- **IPv4 e IPv6 são caminhos separados.** Uma regra de firewall escrita só para IPv4 deixa o IPv6 aberto num host que tem os dois.
- **Endpoints de metadados são locais.** Máquinas de nuvem expõem um serviço de metadados num endereço *link-local*, que só funciona no segmento de rede local. A AWS documenta `169.254.169.254` e, para IPv6, `[fd00:ec2::254]`. O mesmo serviço pode devolver credenciais do papel da máquina, então um convidado que o alcança pode agir como o host.

## Decidir sobre um nome não é decidir sobre um endereço

Uma lista de permissões lista nomes, porque nomes são o que as pessoas aprovam. A conexão, porém, vai para um endereço, e o mapeamento de nome para endereço pertence a quem opera o DNS. O *DNS rebinding* explora essa brecha: a primeira consulta devolve um endereço público e passa na verificação, e uma consulta posterior devolve `169.254.169.254` para a conexão de fato.

A função de decisão do projeto fecha a brecha. Ela resolve uma vez, recusa se *qualquer* resposta não for pública e devolve o único endereço ao qual quem chama deve se conectar:

```python
# file: examples/agent-engineering/src/agentlab/sandbox/egress.py
def check_egress(host: str, port: int, policy: EgressPolicy, resolve: Resolver) -> Decision:
    name = host.lower().rstrip(".")
    if (name, port) not in policy.allowed:
        return Decision(False, f"{name}:{port} is not on the allowlist")
    answers = [ipaddress.ip_address(a) for a in resolve(name)]  # resolved once, then pinned
    if not answers:
        return Decision(False, f"{name} has no addresses")
    for address in answers:
        if not is_public(address):
            return Decision(False, f"{name} resolved to non-public {address}")
    return Decision(True, "allowed", str(answers[0]))
```

O nome é normalizado primeiro, então `API.Supplier-Alpha.example.` com ponto final casa com sua entrada em minúsculas. Um endereço digitado como host, como `169.254.169.254` ou sua grafia decimal, é só mais um nome que não está na lista, e é negado sem ser resolvido. O resolvedor é um parâmetro, então os testes passam um falso e nada toca a rede.

## Endereços que escondem outro endereço

"Público" quer dizer globalmente alcançável, e o módulo `ipaddress` do Python responde isso com `is_global`, usando os registros de propósito especial da IANA. Algumas formas de IPv6 carregam um endereço IPv4 dentro. O Python 3.13 julga um endereço IPv4 mapeado como `::ffff:169.254.169.254` pela parte IPv4, e a faixa 6to4 `2002::/16` não é global. Uma forma escapa. A RFC 6052 define o prefixo NAT64 bem conhecido `64:ff9b::/96`, que um gateway NAT64 traduz para o endereço IPv4 dos últimos 32 bits. A IANA lista esse prefixo como globalmente alcançável, então `is_global` diz que `64:ff9b::a9fe:a9fe` é público, e mesmo assim o gateway o transforma no endereço de metadados. O projeto o desembrulha:

```python
# file: examples/agent-engineering/src/agentlab/sandbox/egress.py
def is_public(address: Address) -> bool:
    """Globally reachable, judging an IPv4 address carried inside IPv6 by the IPv4 part."""
    if isinstance(address, ipaddress.IPv6Address) and address in NAT64:
        return ipaddress.IPv4Address(int(address) & 0xFFFFFFFF).is_global
    # Python 3.13 judges ::ffff:a.b.c.d by its IPv4 part; 6to4 (2002::/16) is not global.
    return address.is_global
```

## Uma decisão não é imposição

`check_egress` só obriga o código que a chama. Código não confiável pode abrir o próprio socket, então o bloqueio real precisa acontecer onde todo pacote passa e o convidado não alcança: um firewall no host, ou um namespace de rede sem rota para fora. O guia de produção do Firecracker diz com todas as letras que, como afirma o seu modelo de ameaças, o Firecracker "does not perform any network traffic filtering" (não faz nenhuma filtragem de tráfego de rede). O mesmo guia mostra uma regra no host que descarta o tráfego do convidado para o endereço de metadados. A regra abaixo foi citada desse guia como ilustração. Ela precisa de um host Linux com as tabelas de rede do Firecracker, e a CI do curso não a executa:

```bash
sudo nft add rule firecracker filter iifname "tap*" ip daddr 169.254.169.254 counter drop
```

Essa regra cobre só IPv4, que é justamente o ponto do segundo item acima. A imposição mais simples para o script de relatório é dar à sua microVM nenhum dispositivo de rede ([aula 17.4](/pt-br/lessons/17-sandboxed-agent-execution/17.4-a-python-interpreter-in-a-microvm/)).

Sandboxes gerenciadas pedem o mesmo cuidado. A documentação da E2B, lida em 2026-10-18, diz "Every sandbox has outbound access to the internet by default" (toda sandbox tem acesso de saída à internet por padrão), e `allow_internet_access=False` o desliga. Ela também avisa que "blocked connections may appear successful from inside the sandbox" (conexões bloqueadas podem parecer bem-sucedidas de dentro da sandbox). Então uma sonda precisa verificar uma resposta real de aplicação, não só um socket conectado.

## Segredos que o convidado nunca vê

O segredo mais barato de proteger é aquele que o convidado nunca recebe. `run_python` inicia o filho com `env={}`, então uma chave de API no ambiente do worker não atravessa. O jailer do Firecracker faz o mesmo com o próprio processo: um dos seus passos documentados é "Cleanup all environment variables received from the parent process" (limpar todas as variáveis de ambiente recebidas do processo pai). Arquivos são o outro meio: nunca coloque um arquivo de credencial na workspace, e não monte nada do host que guarde um.

Dependências pertencem à imagem, não à execução. Um convidado que instala pacotes durante a execução precisa de uma rota até um índice de pacotes. Essa rota é um canal de saída, e o pacote instalado roda o próprio código dentro do convidado. Construa a imagem antes, com versões fixadas, e o convidado não precisa de rede.

## Rode o exercício

O módulo é `src/agentlab/sandbox/egress.py`; os testes estão em `tests/test_sandbox_egress.py`. A partir de `examples/agent-engineering/`, rode `uv run --frozen python -m unittest tests.test_sandbox_egress -v`. Espere `Ran 8 tests` e `OK`.

Os testes de decisão emparelham cada negação com um caso permitido. Um nome da lista com respostas IPv4 e IPv6 públicas passa, enquanto o mesmo nome respondendo com qualquer uma de onze formas não públicas é negado, incluindo um endereço ruim misturado a bons. Um resolvedor de rebinding que muda a resposta na segunda chamada é consultado uma vez só. O teste de ambiente define uma variável canário, `AGENTLAB_CANARY_TOKEN`, no processo de teste e verifica que o filho na sandbox não a vê. Os únicos nomes que ele pode ver são `LC_CTYPE`, que a coerção de locale do CPython define, e `__CF_USER_TEXT_ENCODING`, que o macOS acrescenta. Nenhum dos dois é herdado. Um controle positivo inicia um filho comum e confirma que ele vê o canário, então o ambiente vazio é uma propriedade da sandbox, não do teste.

Para ver o teste do canário pegar um vazamento, troque `env={}` por `env=dict(os.environ)` em `run_python`. `test_the_sandbox_starts_with_an_empty_environment` falha na hora, nomeando o canário. Restaure a linha. Esses testes comprovam a política e o ambiente. Eles não comprovam que algum pacote é bloqueado, o que exige um firewall ou uma VM sem dispositivo de rede e uma sonda que verifique uma resposta real.
