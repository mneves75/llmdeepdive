A DGX Spark sits on a desk and runs from a 240 W supply. The GPU shares a 128 GB pool with the CPU. That is far more than the 24 GB discrete card in lesson 8.9. So will it run Qwen3.8-27B well? Lesson 9.6 split that question in two: does the model load, and how fast does it run? The Spark answers the first one generously and the second one modestly.

Start with the machine. NVIDIA's hardware overview describes the GB10 chip as a Blackwell GPU with 6,144 CUDA cores and fifth-generation Tensor Cores with FP4 support. It sits beside a 20-core Arm CPU, 10 Cortex-X925 cores plus 10 Cortex-A725 cores. Both use one pool of 128 GB LPDDR5x over a 256-bit interface, rated at 273 GB/s. The chip has a thermal design power of 140 W. Two QSFP ports on a ConnectX-7 network adapter allow Sparks to be linked. NVIDIA's compute-capability list gives GB10 the value 12.1, which `nvcc` calls `sm_121`. Lesson 12.3 explains what that name means for your build.

Now the arithmetic, using the method of lessons 9.1 and 9.6: vendor bandwidth divided by artifact size.

$$
\frac{273\ \text{GB/s}}{17.1\ \text{GB}} \approx 16.0\ \text{tok/s}, \qquad \frac{273\ \text{GB/s}}{54\ \text{GB}} \approx 5.1\ \text{tok/s}.
$$

The 17.1 GB artifact is the pinned Q4_K_M GGUF of lessons 7.12 and 8.7. The 54 GB artifact is the bf16 checkpoint. Both quotients are planning heuristics from a vendor figure, not measurements and not hard bounds. Lesson 9.1 lists what moves the real rate: active bytes, cache reads, state updates and unattained bandwidth.

Compare with lesson 11.1, which owns the Mac Studio M5 Ultra quotients of about 70.2 and 22.2 tok/s on the same two artifacts. Both machines divide by the same file sizes, so the gap is only the bandwidth ratio. The M5 Ultra figure of 1,200 GB/s is about 4.4 times 273 GB/s, and 70.2 is about 4.4 times 16.0. On capacity, the Spark's 128 GB is above the 96 GB base M5 Ultra and below its 256 GB and 512 GB configurations. Lesson 11.1 covers them.

What does the capacity buy? The bf16 checkpoint takes 54 of the 128 GB, a little under half. The rest holds the OS, the cache and the recurrent state, with room to spare. Lesson 9.6 put a 32,768-token cache at 2 GiB. That adds about 4 percent to the bytes of the bf16 checkpoint, so on this box context length is not the limit. The weights are. The CPU is Arm, so every package you install must be an aarch64 build. NVIDIA's NGC page says the Spark needs the ARM64 version of its command-line tool, and lesson 12.5 covers the wider consequences.

Prefill is where the Spark spends its arithmetic. NVIDIA states up to 1 PFLOP at FP4 precision with sparsity. That is the narrowest format with a sparsity assumption, the footnote lesson 9.4 warned about. Treat it as a ceiling for a configuration your model may never enter. The direction still holds. An 8,192-token prefill does thousands of operations per weight byte (lesson 9.1). Batch-1 decode does about one. Long prompts, retrieval and evaluation suit this box. A single chat stream is held by 273 GB/s.

Here is the classic wrong turn. A buyer reads "1 PFLOP" and "128 GB" and expects a small data-centre GPU for chat. Run the division first. The same buyer then reaches for a 4-bit format to fix decode, and expects the headline ratio of the format. NVIDIA's own vLLM playbook for the Spark serves a pre-quantized `nvidia/Qwen3.8-27B-NVFP4` checkpoint. Its model card says the recipe is mixed: NVFP4 on the MLP layers and `lm_head`, FP8 on the self-attention and linear-attention layers. A format's ratio applies only to the tensors it covers. The real size is the file on disk. Read it from the Hub, then divide 273 by that number.

:::warning
The 128 GB is not your budget. `nvidia-smi` prints "Memory-Usage: Not Supported" on this chip because an integrated GPU has no dedicated framebuffer. NVIDIA also warns that `cudaMemGetInfo` can report less than is allocatable, because the CPU may free DRAM by swapping pages. NVIDIA's July 2026 release notes also describe a display-reserved memory region of 2 GB by default, switchable to 4 GB in the BIOS. Redo the budget of lesson 9.3 from `MemAvailable`. Swap is not serving capacity.
:::

```bash
nvidia-smi --query-gpu=name,compute_cap --format=csv
grep -E 'MemAvailable|SwapFree' /proc/meminfo
```

The first command prints the compute capability. The second reads the figures NVIDIA's sample code reads.

Pairing is a capacity purchase before it is a speed purchase. NVIDIA's clustering guide gives each QSFP port up to 200 Gb/s, which is 25 GB/s. The NIC reaches the chip through two PCIe Gen 5 x4 links. Local memory is about eleven times faster than one port. Tensor parallelism across two Sparks halves the weight bytes each box reads, but every layer then synchronizes over that port. Lessons 5.8 and 9.9 price that trade. Measure it before you promise a number.

:::caveat
Every hardware figure here is a vendor claim, read on 3 October 2026 from NVIDIA's documentation. A different supply, a partner GB10 system or a later firmware release can change what you see. The software versions on NVIDIA's release-notes page apply to the Founders Edition only.
:::

The durable idea is that the Spark is a capacity machine with modest bandwidth. It makes big models possible and makes single streams slow. Lesson 12.2 keeps the same Grace-and-Blackwell design but adds a second, much faster pool of memory, and shows why having both is not the same as having one fast pool.
