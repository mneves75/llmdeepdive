A DGX Spark sits on a desk and runs from a 240 W power supply. Its GPU (graphics processing unit, the chip that runs model arithmetic) shares a 128 GB pool of working memory with the CPU (central processing unit, the general-purpose processor). That is far more than the 24 GB discrete card in [lesson 8.9](/lessons/8-building-and-serving-stacks/8.9-mlx/) (a discrete card is a separate board with its own memory). So will it run Qwen3.8-27B well? [Lesson 9.6](/lessons/9-hardware-and-infrastructure/9.6-apple-silicon-unified-memory/) split that question in two: does the model load, and how fast does it run? The Spark answers the first one generously and the second one modestly. This lesson shows why, with two divisions you can redo for any machine.

## What is inside the box?

NVIDIA's hardware overview describes the GB10 chip as two processors in one package:

- a Blackwell GPU with 6,144 CUDA cores, the GPU's general-purpose arithmetic units, and fifth-generation Tensor Cores with FP4 support (Tensor Cores are units that multiply small matrices in one step; FP4 is a 4-bit number format);
- a 20-core Arm CPU, 10 Cortex-X925 cores plus 10 Cortex-A725 cores.

Both use one pool of 128 GB LPDDR5x, a low-power type of DRAM (main working memory), over a 256-bit interface rated at 273 GB/s. That rate is the memory **bandwidth**: how many bytes per second the memory can deliver to the processors. The chip has a thermal design power (its heat and power ceiling) of 140 W. Two QSFP ports (sockets for high-speed network cables) on a ConnectX-7 network adapter allow Sparks to be linked.

NVIDIA's compute-capability list gives GB10 the value 12.1, which `nvcc`, NVIDIA's CUDA compiler (the program that turns source code into instructions the GPU runs), calls `sm_121`. Compute capability is NVIDIA's version number for the features a GPU supports. [Lesson 12.3](/lessons/12-dgx-and-cuda/12.3-the-cuda-programming-model/) explains what that name means for your build.

## How fast can one conversation decode?

**Decode** is the phase that produces the answer one token at a time. For each new token, the GPU reads the model's weights from memory, and with a single conversation (batch 1, one request at a time) there is little arithmetic to do on each byte it reads. So the memory is the bottleneck, and [lessons 9.1](/lessons/9-hardware-and-infrastructure/9.1-memory-bandwidth-vs-flops/) and 9.6 turn that into a planning method: vendor bandwidth divided by artifact size.

$$
\frac{273\ \text{GB/s}}{17.1\ \text{GB}} \approx 16.0\ \text{tok/s}, \qquad \frac{273\ \text{GB/s}}{54\ \text{GB}} \approx 5.1\ \text{tok/s}.
$$

The 17.1 GB artifact is the pinned Q4_K_M GGUF of [lessons 7.12](/lessons/7-inference-and-efficiency/7.12-running-models-locally/) and [8.7](/lessons/8-building-and-serving-stacks/8.7-llama-cpp-and-gguf/), a quantized file whose weights are stored in fewer bits than bf16 (a 16-bit floating-point format). The 54 GB artifact is the bf16 checkpoint, the saved file holding the full 16-bit weights. Both quotients are planning heuristics from a vendor figure, not measurements and not hard bounds. Lesson 9.1 lists what moves the real rate: active bytes, cache reads, state updates and unattained bandwidth.

Compare with [lesson 11.1](/lessons/11-mac-studio-ultra-and-mlx/11.1-mac-studio-ultra-as-an-inference-machine/), which owns the Mac Studio M5 Ultra quotients of about 70.2 and 22.2 tok/s on the same two artifacts. Both machines divide by the same file sizes, so the gap is only the bandwidth ratio. The M5 Ultra figure of 1,200 GB/s is about 4.4 times 273 GB/s, and 70.2 is about 4.4 times 16.0. On capacity, the Spark's 128 GB is above the 96 GB base M5 Ultra and below its 256 GB and 512 GB configurations. Lesson 11.1 covers them.

## What does 128 GB of capacity buy?

<Figure id="t12-spark-capacity-split" />

On this box, context length is not the limit; the weights are. Even at 32,768 tokens, the KV cache (the keys and values the model keeps for earlier tokens, [lesson 7.2](/lessons/7-inference-and-efficiency/7.2-the-kv-cache/)) and the recurrent state of the model's linear-attention layers add only 2 GiB (lesson 9.6), about 4 percent of the bf16 checkpoint.

Because the CPU is Arm, every software package you install must be an aarch64 build (the 64-bit Arm instruction family) rather than an x86-64 one (the instruction family used by Intel and AMD desktop chips). NVIDIA's NGC page says the Spark needs the ARM64 version of its command-line tool (a text-based utility run in a terminal), and [lesson 12.5](/lessons/12-dgx-and-cuda/12.5-the-cuda-stack-for-llms/) covers the wider consequences.

## Where does the 1 PFLOP figure apply?

**Prefill**, the phase that reads the whole prompt before the first new token, is where the Spark spends its arithmetic. NVIDIA states up to 1 PFLOP, a quadrillion floating-point (decimal) operations per second, at FP4 precision with sparsity. That is the narrowest format plus a sparsity assumption, the footnote [lesson 9.4](/lessons/9-hardware-and-infrastructure/9.4-nvidia-cuda-hopper-blackwell/) warned about: the hardware may skip a fixed share of weights that are zero (structured sparsity). Treat it as a ceiling for a configuration your model may never enter.

The direction still holds. During prefill, each weight byte read from memory serves many tokens of the prompt at once; in the idealized model, where it serves all of them, an 8,192-token prefill does thousands of operations per weight byte (lesson 9.1). Batch-1 decode does about one. Long prompts, retrieval and evaluation suit this box. A single chat stream is held by 273 GB/s.

## Why a 4-bit checkpoint misses the headline ratio

A buyer reads "1 PFLOP" and "128 GB" and expects a small data-centre GPU for chat. Run the division first.

The same buyer then reaches for a 4-bit format to fix decode, and expects the format's headline ratio. NVIDIA's own vLLM playbook for the Spark serves a pre-quantized `nvidia/Qwen3.8-27B-NVFP4` checkpoint (NVFP4 is NVIDIA's 4-bit format, detailed in lesson 12.5). Its model card says the recipe is mixed: NVFP4 on the MLP layers (the feed-forward blocks) and `lm_head` (the final output layer that produces next-token scores), and FP8 on the self-attention and linear-attention layers. A format's ratio applies only to the tensors (weight arrays) it covers. The real size is the file on disk. Read it from the Hugging Face Hub (the online repository hosting the model), then divide 273 by that number.

:::warning
The 128 GB is not your budget. `nvidia-smi` prints "Memory-Usage: Not Supported" on this chip because an integrated GPU has no dedicated framebuffer, the separate memory a discrete card owns. NVIDIA also warns that `cudaMemGetInfo` can report less than is allocatable, because the CPU may free DRAM by swapping pages (moving inactive memory chunks onto slower storage). NVIDIA's July 2026 release notes also describe a display-reserved memory region of 2 GB by default, switchable to 4 GB in the BIOS (the machine's startup firmware settings). Redo the budget of [lesson 9.3](/lessons/9-hardware-and-infrastructure/9.3-kv-cache-sizing-and-memory-budgets/) from `MemAvailable`, the operating system's estimate of the memory new programs can use without swapping. Swap is not serving capacity.
:::

Before sizing a model on a Spark, run two terminal commands: the first prints the GPU name and compute capability, and the second reads the available-memory and swap counters that NVIDIA's own sample code checks.

```bash
nvidia-smi --query-gpu=name,compute_cap --format=csv
grep -E 'MemAvailable|SwapFree' /proc/meminfo
```

## Does linking two Sparks make one conversation faster?

Pairing is a capacity purchase before it is a speed purchase. NVIDIA's clustering guide gives each QSFP port up to 200 Gb/s, which is 25 GB/s (8 bits to a byte). The NIC, the network card, reaches the chip through two PCIe Gen 5 x4 links (high-speed internal data lanes). Local memory is about eleven times faster than one port.

Tensor parallelism splits each layer's weights across the two boxes. It halves the weight bytes each box reads, but every layer then synchronizes over that port. [Lessons 5.8](/lessons/5-pretraining-at-scale/5.8-model-parallelism/) and [9.9](/lessons/9-hardware-and-infrastructure/9.9-interconnects-and-clusters/) price that trade. Measure it before you promise a number.

:::caveat
Every hardware figure here is a vendor claim, read on 3 October 2026 from NVIDIA's documentation. A different supply, a partner GB10 system or a later firmware release can change what you see. The software versions on NVIDIA's release-notes page apply to the Founders Edition only.
:::

So the Spark is a capacity machine with modest bandwidth. It makes big models possible and makes single streams slow. [Lesson 12.2](/lessons/12-dgx-and-cuda/12.2-dgx-station-hbm-beside-a-big-pool/) keeps the same Grace-and-Blackwell design but adds a second, much faster pool of memory, and shows why having both is not the same as having one fast pool.
