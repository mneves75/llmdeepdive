Most web applications split their code across dozens of files hosted on a server or a content delivery network (CDN). That works well for an online site, until a learner clicks **Save HTML** to keep a portable copy of the chat application—or a static host drops one versioned chunk and breaks the page.

In `examples/qwen-local-lab/`, the build produces a single deterministic document, `dist/index.html`, containing the entire user interface, both inference runtimes, both CPU WebAssembly binaries, the streaming SHA-256 hasher, and all third-party license notices, using only Python's standard library. This lesson walks through the byte arithmetic, reproducible vendor verification, single-read embedding, and dual Content Security Policy generation behind that single-file artifact.

## The base64 math behind 15.66 MB—and why weights stay outside

HTML is a text format, whereas compiled WebAssembly binaries (`.wasm`) contain arbitrary raw bytes that would break an HTML parser if pasted directly into a `<script>` tag. To store binary payloads safely inside HTML, `scripts/build.py` encodes each embedded asset with **base64**, a text encoding that converts every 3 bytes (24 bits) into 4 printable ASCII characters (6 bits each).

That conversion carries an exact size multiplier of $\frac{4}{3} \approx 1.333$ (+33.3% overhead). As broken down in the stack above, the five locked vendor binaries in `vendor/lock.json` (`webllm.js`, the multi- and single-thread `wllama` WASM binaries, patched `wllama.js`, and `hash-wasm.js`) total **11,659,803 bytes** (**11.66 MB**) raw. Multiply by $\frac{4}{3}$:

$$
11{,}659{,}803 \times \frac{4}{3} \approx 15{,}546{,}404\ \text{B} \approx 15.55\ \text{MB}
$$

Because each of the five vendor payloads is base64-encoded and padded separately to a 4-byte boundary, those five blocks occupy **15,546,408** base64 bytes inside the **15,658,390-byte** (**15.66 MB**) `dist/index.html` alongside roughly **0.11 MB** of plain UTF-8 HTML, CSS, `src/app.js`, base64-encoded `src/inference-worker.js`, third-party license notices, and the `<meta>` CSP. Initial page paint does not decode those binaries; instead, `app.js` decodes each `<script type="application/octet-stream">` tag back into raw bytes via `atob()` on **Load** (`embeddedAssets()`) and hands the worker local `blob:` URLs.

Now apply the exact same arithmetic to the **639.45 MB** (`639,446,688` bytes) Qwen3-0.6B Q8_0 GGUF weights from [lesson 34.4](/lessons/34-a-model-in-your-browser/34.4-streaming-and-verifying-weights/):

$$
639.45\ \text{MB} \times \frac{4}{3} \approx 852.6\ \text{MB}
$$

Adding those ~852.6 MB of base64 weights to the ~15.7 MB of runtimes and UI would inflate the full `dist/index.html` to roughly **868 MB**—an HTML document that browsers struggle to parse into a DOM tree and duplicate in JavaScript strings during `atob()`. Keeping the runtime inside `dist/index.html` and the weights in Cache API or a user-selected local GGUF file gives portability without breaking browser memory limits.

## Rebuilding vendor files without npm install

Traditional JavaScript builds run `npm install`, pulling hundreds of transitive dependencies and lifecycle scripts onto the developer's machine. Because `qwen-local-lab` needs only three prebuilt browser libraries (`@wllama/wllama@2.3.7`, `@mlc-ai/web-llm@0.2.89`, and `hash-wasm@4.13.0`), `scripts/fetch_vendor.py` downloads each official tarball straight from `https://registry.npmjs.org/` and verifies its npm **sha512** integrity digest before opening the archive at all.

The `check_integrity` function computes the base64-encoded SHA-512 hash of the downloaded archive bytes and aborts immediately if a single bit differs from `vendor/lock.json`.

```python
# file: examples/qwen-local-lab/scripts/fetch_vendor.py
def check_integrity(data, integrity, label):
    expected = integrity.removeprefix('sha512-')
    actual = base64.b64encode(hashlib.sha512(data).digest()).decode('ascii')
    if actual != expected:
        raise VendorError(f'{label}: tarball integrity mismatch (expected sha512-{expected}, got sha512-{actual})')
```

After verifying the archive, `read_members` extracts only the explicitly listed regular files—refusing absolute paths, `..` path traversal, symbolic links, or duplicate archive entries.

One extracted file needs a targeted fix: upstream `wllama 2.3.7` resolves asset URLs with `new URL(relativePath, document.baseURI)`, which throws inside a Web Worker where `document` does not exist. The committed one-line patch `vendor/patches/wllama-worker-base-url.patch` substitutes `typeof document === "undefined" ? self.location.href : document.baseURI` without touching any inference math. To ensure an upstream change never applies that edit silently in the wrong place, `apply_patch` requires every hunk to match **exactly once**.

```python
# file: examples/qwen-local-lab/scripts/fetch_vendor.py
def apply_patch(text, patch_text, label):
    for old, new in parse_hunks(patch_text, label):
        count = text.count(old)
        if count != 1:
            raise VendorError(f'{label}: patch hunk matches {count} times; it must match exactly once')
        text = text.replace(old, new)
    return text
```

Finally, `build_outputs` checks every extracted (and patched) output's exact byte length and SHA-256 against `vendor/lock.json` in memory before `run()` writes a single file to `vendor/`. If any check fails, the script exits with status 1 and writes nothing.

## One verified read into memory avoids a swap bug

When a build script verifies a file on disk (`hash(open(path))`) and then opens the same path a second time to embed it (`encode(open(path))`), it creates a **Time-Of-Check to Time-Of-Use (TOCTOU)** window—a race condition where a modified file could slip in between verification and assembly.

`scripts/build.py` eliminates that window by reading each locked file into memory once inside `vendor_files()`, verifying its SHA-256 against `vendor/lock.json`, and returning those exact in-memory bytes straight to the base64 encoder.

```python
# file: examples/qwen-local-lab/scripts/build.py
def vendor_files(root):
    """Return the lock's verified asset bytes and notice texts, failing if any file is absent or altered."""
    lock = json.loads((root / 'vendor/lock.json').read_text(encoding='utf-8'))
    assets, notices = {}, []
    for package in lock['packages']:
        for entry in package['files']:
            path = root / 'vendor' / entry['output']
            if not path.is_file():
                raise BuildError(f'vendor/{entry["output"]} is missing; run scripts/fetch_vendor.py')
            data = path.read_bytes()
            if hashlib.sha256(data).hexdigest() != entry['sha256']:
                raise BuildError(f'vendor/{entry["output"]} does not match vendor/lock.json; run scripts/fetch_vendor.py')
            if entry['embed'] == 'notice':
                notices.append((path.name, data.decode('utf-8')))
            else:
                assets[entry['embed']] = data
    return assets, notices
```

## Hashing the inline script and styles into two CSP targets

Because `dist/index.html` inlines `src/app.js` and its CSS styles, a naive Content Security Policy might reach for `'unsafe-inline'`—which would allow any injected script tag to run. Instead, `content_security_policy()` hashes the exact inline `<script type="module">` body and every inline `<style>` block with SHA-256 and locks the policy to those exact digests.

```python
# file: examples/qwen-local-lab/scripts/build.py
def content_security_policy(html):
    """Return (header policy, meta policy) allowing exactly the inline blocks in html."""
    scripts = INLINE_SCRIPT.findall(html)
    if len(scripts) != 1:
        raise BuildError(f'expected exactly one inline module script, found {len(scripts)}')
    styles = ' '.join(dict.fromkeys(source_hash(style) for style in INLINE_STYLE.findall(html))) or "'none'"
    directives = [
        "default-src 'none'",
        f"script-src {source_hash(scripts[0])} blob: 'wasm-unsafe-eval'",
        'worker-src blob:',
        f'connect-src blob: {MODEL_HOSTS}',
        f'style-src {styles}',
        'img-src data:',
        "object-src 'none'",
        "base-uri 'none'",
        "form-action 'none'",
    ]
    # Browsers ignore frame-ancestors in a <meta> policy and log an error for it.
    return '; '.join(directives + ["frame-ancestors 'none'"]), '; '.join(directives)
```

Notice the two return values. `build.py` writes the first string—including `frame-ancestors 'none'`—into `dist/_headers` alongside `Cross-Origin-Opener-Policy: same-origin` and `Cross-Origin-Embedder-Policy: require-corp` (the HTTP headers that unlock multi-threaded WebAssembly). It writes the second string into `<meta http-equiv="Content-Security-Policy">` inside `dist/index.html` so even a saved copy opened without a custom header file keeps its script, style, worker, and network restrictions. Omitting `frame-ancestors 'none'` from `<meta>` is required by the CSP specification: browsers ignore that directive in meta tags and log a console error if it appears there.

## When one HTML file wins—and when a multi-file build is better

Single-file packaging is a deliberate engineering trade-off rather than a universal default:

- **Where one HTML file wins:** zero broken asset paths when saved via **Save HTML**, atomic deployment (no mismatch between an old HTML shell and a new worker script), and a reproducible SHA-256 over the entire application.
- **Where a multi-file build wins:** smaller initial transfer (no 33.3% base64 inflation, and the browser downloads only the engine you pick instead of both `wllama` and `WebLLM`), independent browser caching of unchanged vendor bundles across app updates, and zero `atob()` decoding time when clicking Load.

In [lesson 34.8](/lessons/34-a-model-in-your-browser/34.8-measuring-browser-inference/), we put the finished artifact on real machines, measure how fast it actually runs, and draw a bright line between what those runs prove and what remains unverified.
