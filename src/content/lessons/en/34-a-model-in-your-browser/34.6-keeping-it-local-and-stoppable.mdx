Putting a 600-million-parameter neural network inside a browser tab introduces three failure modes that ordinary web pages rarely face. Heavy matrix math can freeze every button and scrollbar on the page, a stuck prompt prefill can ignore a Stop button for ten seconds, and an untrusted model string or stray runtime request can break the promise that prompts stay local on your device.

Building on the tab architecture of [lesson 34.1](/lessons/34-a-model-in-your-browser/34.1-what-runs-where/) and the turn loop of [lesson 34.5](/lessons/34-a-model-in-your-browser/34.5-chat-tokens-and-context/), this lesson examines the four runtime guards in `examples/qwen-local-lab/`: Web Worker isolation, two-stage cancellation, safe DOM rendering, and network/device-loss boundaries—along with an honest accounting of what those guards cannot prove by themselves.

## One message channel between page and worker

Browsers run page layout, clicks, typing, and painting on a single **main thread**. Running a transformer forward pass directly on that thread would lock the entire tab until generation finished, making a Stop button impossible to click.

To keep the interface responsive, `src/app.js` moves both inference engines into a dedicated **Web Worker**—a separate background JavaScript thread launched from an embedded `blob:` URL (`new Worker(workerURL, { type: 'module' })`). The main page and the worker share no variables; they communicate exclusively through asynchronous **Remote Procedure Call (RPC)** messages sent via `postMessage()`:

- **Page to worker:** `load`, `generate`, `reset`, and `clearCache`, each tagged with a newly allocated, monotonically increasing numeric request `id`; plus `stop`, which sends `{ type: 'stop', id: state.activeId }` reusing the active request ID rather than allocating a fresh one.
- **Worker to page:** `progress`, `context`, `token`, `done`, `loaded`, `resetDone`, `cacheCleared`, and `error`, echoing that `id` so stale messages from a cancelled turn are ignored.

Only one operation runs at a time (`beginOperation` rejects concurrent commands with `BUSY`), which prevents a race between clearing caches, resetting the KV state, and streaming tokens.

## Cooperative stop and the three-second hard kill

Stopping a local model cleanly is harder than cancelling a network request. In JavaScript, an **AbortController** provides a cooperative cancellation signal: code that periodically checks `signal.aborted` can stop politely between tokens and keep the model loaded in memory for the next question.

Inside `src/inference-worker.js`, `handleStop` triggers that polite path on both backends—setting `op.stopped = true`, aborting the controller for `wllama`, and calling `runtime.interruptGenerate()` (or `runtime.unload()` during loading) for `WebLLM`.

```js
// file: examples/qwen-local-lab/src/inference-worker.js
function handleStop() {
  const op = operation;
  if (!op || !["load", "generate"].includes(op.kind)) return;
  op.stopped = true;
  op.controller.abort();
  if (backend === "webgpu" && runtime) {
    if (op.kind === "load") void runtime.unload().catch(() => {});
    else void runtime.interruptGenerate().catch(() => {});
  }
}
```

During token-by-token decode, cooperative stop responds almost instantly—in our Apple M5 Pro verification, stopping mid-generation halted cleanly at 48 tokens, kept the partial reply, and returned the tab straight to `ready` without reloading weights.

During **prompt prefill**, however, a slow single-thread WebAssembly engine can spend several seconds inside one blocking C++ call before control returns to JavaScript to read the abort signal. To guarantee the learner is never trapped behind a frozen Stop button, `src/app.js` pairs cooperative stop with a hard $3{,}000\ \text{ms}$ ($3\ \text{s}$) fallback timer that calls `destroyWorker()` (`worker.terminate()`).

```js
// file: examples/qwen-local-lab/src/app.js
function stop() {
  if (state.phase === 'loading') {
    destroyWorker();
    $('downloadStatus').textContent = 'Loading cancelled. You can retry when ready.';
    setPhase('idle','Loading cancelled');
    return;
  }
  if (state.phase !== 'generating') return;
  setPhase('stopping');
  state.worker.postMessage({type:'stop',id:state.activeId});
  // A blocked native prefill may not process an abort promptly. Terminating the
  // owning worker also terminates its nested WASM workers and frees the model.
  state.stopTimer = setTimeout(() => {
    destroyWorker();
    finishGeneration({text:state.current?.text || '',stopped:true,metrics:{}});
    $('downloadStatus').textContent = 'Stopped and released the model. Load it again to continue.';
    setPhase('idle','Stopped · model released');
  },3000);
}
```

Why does terminating the wrapper worker also stop `wllama`'s background threads? Under the HTML specification, calling `worker.terminate()` kills the worker immediately and terminates any **nested workers** it spawned, freeing the WebAssembly memory heap. The trade-off is deliberate: the learner gets control back within three seconds, partial text stays in the transcript (or if zero tokens arrived, the prompt returns to the input box and is excluded from future context), and the model moves to `idle` so the learner can reload it when ready.

## Keeping model output inert with textContent

Even a local model with no internet access can produce arbitrary characters, including HTML tags such as `<script>` or `<img onerror="...">`—either by chance, from a code-generation prompt, or from text pasted into the chat box. Assigning model text to `innerHTML` would tell the browser's Document Object Model (DOM) parser to interpret those tags as live markup, creating a **Cross-Site Scripting (XSS)** vulnerability.

`src/app.js` avoids HTML parsing entirely for conversation content. Both `addMessage()` and the streaming `token` handler write directly to `content.textContent = text`. The browser treats `textContent` strictly as literal Unicode characters, so `<script>alert(1)</script>` appears on screen as ordinary text and can never execute.

## What the fetch guard and CSP enforce—and what they do not

"Prompts never leave the browser" is an architectural claim, so `qwen-local-lab` backs it with two separate runtime boundaries.

First, at the top of `src/inference-worker.js`, the wrapper worker replaces `self.fetch` with a guard that normalizes every requested URL and rejects any `http:` or `https:` call whenever the current operation is not `'load'`.

```js
// file: examples/qwen-local-lab/src/inference-worker.js
const nativeFetch = self.fetch.bind(self);
self.fetch = async (resource, options) => {
  const value = resource instanceof Request ? resource.url : String(resource);
  const url = new URL(value, self.location.href);
  if (['http:', 'https:'].includes(url.protocol) && operation?.kind !== 'load') {
    throw new AppError('Network access is disabled during local generation. Reload the model if an asset is missing.', 'NETWORK_DURING_GENERATION');
  }
  return nativeFetch(resource instanceof Request ? resource : url.href, options);
};
```

Second, the page ships with a strict **Content Security Policy (CSP)**—a browser-enforced allowlist of where scripts, workers, and network connections may come from. As we examine in [lesson 34.7](/lessons/34-a-model-in-your-browser/34.7-shipping-as-one-file/), `default-src 'none'` blocks unlisted origins by default, `script-src` permits only the exact SHA-256 hash of the embedded module script plus `blob:` and `'wasm-unsafe-eval'`, and `connect-src` allows only `blob:`, `https://huggingface.co`, `https://*.hf.co`, and `https://raw.githubusercontent.com`.

An honest engineer also states where these boundaries end:

- **The `self.fetch` guard is not a browser-wide network firewall.** It intercepts direct `fetch()` calls inside the wrapper worker. It does not inspect OS-level packets, browser extensions, or a nested worker that creates its own transport, although nested worker assets here are embedded and generation contains no network calls.
- **No packet capture or airplane-mode test was run in `VERIFICATION.md`.** What is verified is zero external HTTP requests logged by Chromium's network inspector during generation, plus unit tests proving the guard rejects direct HTTP fetches outside loading.
- **`connect-src` must still allow the model hosts.** Because the page fetches weights during `load`, the browser's CSP cannot forbid Hugging Face during generation while permitting it during loading; that phase distinction is enforced by application state and the worker guard.

## Recovering from WebGPU device loss without losing the chat

A browser GPU is a shared system resource. Sleep/wake cycles, driver resets, or another tab exhausting graphics memory can trigger a **WebGPU device loss** right in the middle of a turn, leaving the loaded `MLCEngine` unusable.

When `onmessage` inside `src/inference-worker.js` catches an error whose normalized code is `GPU_UNAVAILABLE` during generation, it explicitly disposes the broken runtime and attaches `unloaded: true` to the error reply.

```js
// file: examples/qwen-local-lab/src/inference-worker.js
      const details = errorDetails(error, op);
      const shouldDispose = op?.kind === "load" || (op?.kind === "generate" && details.code === "GPU_UNAVAILABLE");
      if (shouldDispose) {
        try { await disposeRuntime(); } catch { /* The caller can replace a failed worker. */ }
      }
      reply(message.id, "error", { ...details, ...(shouldDispose && op?.kind === "generate" ? { unloaded: true } : {}) });
    }
```

When `src/app.js` sees `data.unloaded`, it clears `state.backend = null`, keeps every earlier message and any partial reply visible in the transcript, and transitions the page from `generating` back to `idle`. The learner sees a clear banner explaining that the GPU device was lost and can reload WebGPU or switch to CPU / WebAssembly without losing their conversation.

With the worker boundary, stop fallback, and safety guards in place, [lesson 34.7](/lessons/34-a-model-in-your-browser/34.7-shipping-as-one-file/) shows how the entire application and both engines are verified and packed into a single deterministic HTML file.
