You now hold two **mixers**, the part of a block that moves information between positions, and a design problem: which one should each layer use?

## Two mixers, two prices

**Full attention** keeps the keys and values of every past token. A query can therefore address any past position directly, by its content, the way you look something up by value rather than by index. Direct access does not guarantee the model recovers that position word for word. The price is storage: keys and values for the entire context, re-read at every step.

**Gated DeltaNet** ([lesson 4.15](/lessons/4-transformer/4.15-gated-deltanet/)) is cheap. Its state has a constant size, and each new token costs the same at any length. The price is lossy learned compression: a fixed-size board cannot promise perfect recall of an arbitrary clipping from half a million tokens ago.

A model that wants a 262,144-token native context must decide, layer by layer, which price to pay. Qwen3.8-27B's answer is a **hybrid layout**: a four-layer motif (Gated DeltaNet, DeltaNet, DeltaNet, full attention) repeated sixteen times. That is 48 DeltaNet layers and 16 attention layers: in the newsroom of the analogy, one archivist every fourth floor.

## Where does long-context memory actually go?

Work the memory consequences step by step, because the intuitive reading gets them backwards. The reflex says: forty-eight recurrent layers, each dragging a state matrix from token to token, must be where long-context memory goes, and the sixteen attention layers must be a rounding error.

Now check each type against what it actually stores. The rest of this section is about **decode**, the phase where the model generates one token at a time.

- A **DeltaNet layer's** state is a fixed set of matrices, edited in place. Token 200,000 costs exactly what token 200 cost, and the layer stores nothing per token.
- An **attention layer** is the opposite. Its direct access to every position relies on storage: every generated token appends keys and values that all future queries may consult. So its memory grows linearly with context, and that growth is multiplied across all sixteen such layers.

At the full native window the totals are not close. The sixteen attention layers' key-value cache runs to roughly 16 GiB per sequence. All forty-eight DeltaNet states together occupy about 144 MiB, constant in length, when the reference implementation keeps recurrent state in fp32 (32-bit floats); another runtime dtype would change the byte count. That is a contrast of more than two orders of magnitude, in the *opposite* direction from the reflex.

[Lesson 7.2](/lessons/7-inference-and-efficiency/7.2-the-kv-cache/) derives both numbers from the head counts and dimensions. Here the shape of the result is what matters: the minority layer type dominates the memory bill precisely because it is the type that remembers everything.

## Why three DeltaNet layers for every attention layer?

That asymmetry is the whole argument for the ratio. Consider the two extremes:

- If every layer were full attention, the growing cache would be four times larger, and long contexts would price themselves out of memory.
- If every layer were DeltaNet, the model would face needle-in-a-haystack retrieval with only lossy summaries. A needle-in-a-haystack task looks like this: quote the exact serial number from page two of a four-hundred-page document.

The 3:1 mixture keeps direct retrieval routes *available* while making their cost the exception rather than the rule. Recall demands are sparse in real workloads. But when one arrives, some layer must be able to address the relevant positions without first compressing them into fixed state.

## How do two layer types work as one model?

What makes the mixture work as one model, rather than two interleaved ones, is the block contract from [lesson 4.11](/lessons/4-transformer/4.11-full-transformer-block/). Both layer types read the same 5120-wide **residual stream**, the running vector each layer reads from and adds its update to. Both pass it through the same pre-norm RMSNorm, and both add back updates of the same shape.

Count floors from 0, as the checkpoint's layer indices do: floors 0 to 2 are DeltaNet and floor 3 is the first attention layer. A retrieval performed by the attention layer on floor 3 is a representation routed from a distant token by content-addressed attention. It is written into the stream. There the DeltaNet layers on floors 4 through 6 can transform it, route it, and build on it with their cheap machinery.

The archivist retrieves; the editors process. The shared board coordinates the work, and the identical gated FFN (the feed-forward block) does the heavy feature transformation on every floor of both kinds.

## Which layers do which jobs?

The layout also shapes *where* different capabilities can live.

Some operations benefit from direct access to arbitrary positions: copying a long identifier, matching a bracket opened 100,000 tokens ago, or **induction** over distant repetitions (having seen "A B" earlier, predicting B the next time A appears). Only the sixteen attention layers offer that direct access, because only they can address any position without squeezing the past into a fixed-size state. The DeltaNet layers can still recover some of this from their compressed state, but not with the same direct, position-by-position access.

Other work sits naturally in the DeltaNet majority: processing weighted toward recent tokens, local composition, and accumulating a running state. Their kernel-4 convolution and gated state handle short- and medium-range structure without touching a growing store.

Interpretability work on hybrid models starts from this map. If a behavior needs direct long-range access, you know which sixteen layers to search.

## Where the pattern comes from, and where it leads

:::warning
The common misconception is to read the hybrid as "a proper Transformer with 48 degraded layers", an approximation of some full-attention original. The model card publishes no full-attention original, and the released checkpoint is this architecture: its configuration and weights define 48 DeltaNet layers, not 48 approximations of something else. How it was trained is not published. Its DeltaNet layers are not compressed softmax attention: at decode time they form no score matrix over the past, only a fixed-size state (lesson 4.15 shows where chunk-local query–key products appear during training). The equally wrong mirror image is "recurrent layers accumulate the long-context memory bill". They are the one part of the model whose memory does not grow at all.
:::

:::note
The Signal Observatory on the explore page shows one classic attention block. In Qwen3.8-27B this exact block appears once every four layers; the other three replace attention with Gated DeltaNet (lesson 4.15).
:::

Qwen did not invent the pattern. 2025–26 produced a family of such designs, interleaving state-space or linear-attention blocks with full attention in Jamba-style and Granite-H lineages. But a 3:1 ratio is among the more aggressive publicly documented at this scale. The checkpoint you read in [lesson 4.14](/lessons/4-transformer/4.14-reading-real-weights/) shows the motif directly: three layers of `linear_attn` machinery, one layer of `self_attn` projections, sixteen times over.

Where this leads is inference. The hybrid layout is a bet about serving economics. The bet is that a model can keep attention's retrieval quality while shrinking the memory that grows per token to a quarter of the layers, and that this decides which contexts, batch sizes, and hardware are feasible. Pricing that bet requires deriving the cache arithmetic properly: bytes per token per layer, per sequence, per gigabyte of accelerator memory. That derivation, including the full 16 GiB versus approximately 144 MiB reference-fp32 accounting this lesson only sketched, is lesson 7.2, where the KV cache gets its own treatment.
