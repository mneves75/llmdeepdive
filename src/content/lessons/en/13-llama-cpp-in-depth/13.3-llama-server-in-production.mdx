A server is a scheduler with an HTTP face. Lesson 7.8 explained continuous batching in the abstract. Here you meet the flags that control it in `llama-server`. Every flag below comes from the `tools/server/README.md` at `b11380`. The slot, batching, cache-type, prompt-reuse, API-key and metrics settings were run against a server on 127.0.0.1, with Qwen3-1.7B Q8_0 as a stand-in model. The caveat at the end lists the flags that were read but not run. Paths and keys are placeholders.

```
llama-server -m MODEL.gguf -c 16384 -np 4 -fa on -ctk q8_0 -ctv q8_0 \
  --metrics --api-key-file KEYS.txt --host 127.0.0.1 --port 8080
```

## Slots and the context

A **slot** is one independent conversation with its own position in the KV cache. `-np` sets how many there are, and the README default is `-1`, meaning auto. In `server.cpp` auto means four slots and a **unified** KV pool, and an explicit `-np` turns that default off. The classic assumption is that `-c` is divided among the slots. That is only half true, and the log shows both halves:

| Command | Log line |
|---|---|
| `-c 8192` | `n_slots = 4, n_ctx_slot = 8192, kv_unified = 'true'` |
| `-c 8192 -np 4` | `n_slots = 4, n_ctx_slot = 2048, kv_unified = 'false'` |

`GET /slots` returned the same `n_ctx` per slot, and Homebrew build 11146 printed the same two lines. In the unified case each slot may grow to the whole pool, but the four of them together still fit in 8192 tokens. In the explicit case the code divides `-c` by the slot count and pads to a multiple of 256, so no slot can exceed 2048. The first is better when requests differ in length. The second gives a hard per-user ceiling. Adding `-kvu` turns the unified pool back on: `-c 8192 -np 4 -kvu` logged `n_ctx_slot = 8192` and `kv_unified = 'true'`. `--kv-unified-per-slot N` sizes the pool as slots times N when you leave `-c` out. Lesson 9.3 owns the memory budget for the context you choose.

## Batching, cache types, flash attention

Continuous batching is on by default (`-cb`). Two 200-token generations sent at once gave `llamacpp:n_busy_slots_per_decode` 1.957. Almost every decode call carried tokens from both slots, which is the point of the feature.

`-ctk` and `-ctv` set the K and V cache types. The README allows `f32, f16, bf16, q8_0, q4_0, q4_1, iq4_nl, q5_0, q5_1`, default `f16`. The V cache has a rule: `-ctv q8_0 -fa off` exited with status 1 and `quantized V cache requires flash_attn to be enabled`, on both builds. With `-fa` at its default of `auto`, `-ctk q8_0 -ctv q8_0` started. A smaller cache fits more slots, and the quality cost is yours to measure with lesson 13.2's tools.

## Prompt reuse

`--cache-prompt` is on by default. The test sent a 547-token chat prompt, then the same system text with a different last message. The second reply reported `cache_n` 536 and `prompt_n` 11. With `cache_prompt` set to `false` it evaluated 547 again. Three related controls exist: `--cache-reuse N` tries to reuse chunks by shifting the KV cache (default 0, off), `--cache-ram` caps the host-memory prompt cache (default 8192 MiB), and `--slot-save-path` enables `POST /slots/{id}?action=save` and `restore` for explicit snapshots. For reuse to work, put what changes at the end of the prompt.

## At the limit

What happens when a conversation outgrows its slot? `--context-shift` decides whether the server may discard old tokens to keep generating, and the README lists it as disabled by default. The overflow path was not tested, so check it with your own client before launch: send a prompt longer than `n_ctx_slot` and see whether you get an error, a truncation or a shift. Two more flags matter for long jobs. `-to` sets the read and write timeout in seconds (default 3600), and `--sleep-idle-seconds` lets an idle server unload its model and KV cache (default off). `GET /slots` shows each slot's `n_ctx` and whether it is processing, and `?fail_on_no_slot=1` returns 503 when none is free, which suits a load balancer's health probe.

## Doors, locks and gauges

`--jinja` is enabled by default, so the server renders the model's own chat template. `POST /apply-template` returns the rendered prompt, which is the quickest way to see what the model actually receives. Qwen3 templates read `enable_thinking`, which the tests set per request with `chat_template_kwargs`; `--chat-template-kwargs` sets it for the server.

The endpoints are the OpenAI routes (`/v1/chat/completions`, `/v1/responses`, `/v1/embeddings`), the Anthropic route (`/v1/messages`), and the native `/completion`, `/tokenize`, `/props`, `/slots` and `/metrics`.

`--host` defaults to `127.0.0.1`. Without a key the log warns `no API key is set and CORS allows all origins`. With `--api-key` or `--api-key-file` (one key per line, `#` for comments), the measured statuses were:

| Request | Status |
|---|---|
| `/health`, no key | 200 |
| `/v1/models`, no key | 401 |
| `/metrics`, no key | 401 |
| `/metrics`, `Authorization: Bearer KEY` | 200 |
| `/v1/models`, `X-Api-Key: KEY` | 200 |

Only `/health` and `/v1/health` are public, plus the web UI assets. `/metrics` is off unless you pass `--metrics`, and your scraper then needs the key. It exports Prometheus counters such as `llamacpp:prompt_tokens_total` and `llamacpp:tokens_predicted_total`, and gauges such as `llamacpp:requests_processing` and `llamacpp:n_busy_slots_per_decode`. The exporter also printed `llamacpp:prompt_tokens_cached_total`, which the README table does not list.

:::warning
An API key on the command line is visible in the process list, so prefer `--api-key-file`. For a public deployment, the README advises an API key and a reverse proxy. `--tools` is marked experimental and `--agent` carries the README's warning not to enable it in untrusted environments. They expose file access and a shell tool, so leave them off on a shared server.
:::

:::caveat
These flags come from the README only and were not run: `--cache-reuse`, `--cache-ram`, `--slot-save-path`, `--context-shift`, `-to`, `--sleep-idle-seconds`, `--kv-unified-per-slot`, `--chat-template-kwargs`, `--tools` and `--agent`. TLS (`--ssl-key-file`, `--ssl-cert-file`), router mode (`--models-dir`) and the multi-key list were not tested either.
:::

The durable idea: a server has three budgets, the context pool, the slots that share it and the cache types that shrink it. Choose them from the traffic, then read the startup log to confirm what you got. Next, lesson 13.4 measures the result with `llama-bench`.
