The purchasing assistant computes invoice lines in a small module, `pricing.py`. Orders of ten units or more get a 5% bulk discount, so ten boxes of gloves at USD 12.00 should cost USD 114.00. The invoice says USD 120.00. You ask a model to fix it. It proposes a patch, and a second model call reviews the patch and replies that it looks good. Is the bug fixed? This track builds a repair loop that answers that question with a measurement, and this lesson sorts the signals the loop can receive into the ones that measure the code and the ones that only advise.

## What signals can a repair loop receive?

A *repair loop* runs a check, asks a model for a change when the check fails, applies the change and runs the check again. Its *feedback* is whatever comes back from each run. Six kinds come back from the exercise's runs:

- **Syntax errors.** Python could not even compile the module. The error names a file and a line.
- **Failed assertions.** A test compared the code's answer with the expected one and they differed: `Decimal('120.00') != Decimal('114.00')`.
- **Runtime errors.** Some other exception escaped, such as a `TypeError` from adding `None` to a price.
- **Resource limits.** The run was stopped by a CPU or wall-clock limit, the kind [lesson 17.2](/lessons/17-sandboxed-agent-execution/17.2-resource-and-filesystem-limits/) sets. A loop that never ends produces no traceback, only this.
- **Environment failures.** The machine is wrong rather than the code: a package is missing, or the sandbox could not start.
- **Critic opinions.** A person or another model read the patch and says what they think of it.

The first four are *corrective feedback* in the sense this track uses: each one measures the code against a stated expectation, and you can repeat the measurement after a change and get a new answer. The fifth measures the environment, which the loop cannot change by editing files. The sixth is not a measurement at all.

## Why a critic's approval is not a measurement

A critic can be useful. Self-Refine (Madaan et al., 2023) has one model draft an answer, give feedback on its own draft and revise it, with no extra training. Across seven tasks the authors report about 20% absolute improvement on average over single-pass generation. Reflexion (Shinn et al., 2023) feeds an agent's verbal reflections on earlier attempts into later ones, and accepts feedback that is scalar or free-form and external or internally simulated.

The caution comes from a different study of reasoning tasks. Huang et al. (2023) looked at *intrinsic* self-correction, where a model revises its answer using only its own judgement, with no outside feedback. They found that models struggle to correct themselves that way, and that performance sometimes gets worse after the revision. A critic that says "looks good" about a patch is intrinsic feedback of exactly this kind unless it is backed by a run.

So the loop treats the two kinds of signal asymmetrically. A test result decides. A critic may add doubt, never remove it:

```python
# file: examples/agent-engineering/src/agentlab/repair/feedback.py
def next_step(feedback: Feedback, critic: Literal["approve", "object"] | None = None) -> Step:
    """Tests decide; a critic can only add doubt."""
    if feedback.kind == "environment":
        return "escalate"
    if feedback.kind != "passed":
        return "repair"  # whatever the critic said
    return "escalate" if critic == "object" else "accept"
```

When the tests fail, the critic's verdict is never read. When they pass and the critic objects, a person looks, because a passing suite can still miss something a reader noticed. *Escalate* means stop and hand the case to a person with everything the loop learned.

:::insight
The control flow is the safeguard. An instruction in the critic's prompt saying "only approve if the tests pass" would be a request to a model; the `if` above is code the model cannot argue with.
:::

## Exit code zero is not a pass

A test runner reports through its exit code and its printed summary, and a careless loop reads only the exit code. Qi et al. (2015) analysed patches that earlier automatic repair systems had reported as successful. One test harness checked only part of the exit code of a test script, and the patch under evaluation could change how that script behaved. Of 167 accepted patches for one program, 138 did not pass all of the test cases.

The exercise reproduces the trap. The code under test runs inside the same Python process as the test runner, so a patched module can call `sys.exit(0)` while it is being imported. The process exits with code 0 and no test ever ran. A patch can also make every test skip: unittest then prints `OK (skipped=3)` and still exits with 0. Its documentation defines `skipped` as a separate list of tests, apart from failures and errors.

The loop's runner therefore prints one summary line of its own after the tests, and `classify` counts a run as passed only on these terms:

```python
# file: examples/agent-engineering/src/agentlab/repair/feedback.py
    if run.ran is not None and not run.failed and not run.skipped and run.ran >= max(minimum_tests, 1):
        return Feedback("passed", f"{run.ran} tests passed")
```

`run.ran is None` means the summary never appeared. `minimum_tests` is the number of tests the initial, unpatched run executed: a patch cannot delete a protected test, but it can stop tests from running. Anything that fails these terms and has no traceback is classified `incomplete`, which the loop treats like any other failure.

:::caveat
These checks catch honest mistakes and lazy shortcuts. A patch written on purpose to forge its own results, for example by replacing unittest's assertion methods, defeats them, because it runs in the same process. The defences against that are reading the diff ([lesson 21.3](/lessons/21-bounded-agent-self-correction/21.3-repair-with-a-bounded-context/) keeps patches small for this reason) and tests the loop never sees ([lesson 21.5](/lessons/21-bounded-agent-self-correction/21.5-evaluate-a-correction/)).
:::

## Environment failures go to a person

If the initial run fails with `ModuleNotFoundError: No module named 'invoice_rates_service'`, the loop could ask the model to delete the import, and the tests might then load. That patch might also drop the very thing the code needs. The loop may only change `pricing.py`; it cannot install a package or repair a sandbox. `classify` labels a missing module and a sandbox that failed to start as `environment`, and `next_step` escalates both without asking the model for anything.

This also keeps the loop's graph honest. [Lesson 14.2](/lessons/14-agent-architecture-and-state/14.2-states-dags-branches-and-loops/) showed a cycle bounded by a step budget; here the cycle runs only for failures a patch could plausibly fix, and [lesson 21.4](/lessons/21-bounded-agent-self-correction/21.4-budget-the-repair-loop/) bounds it.

## Run the exercise

The modules are `src/agentlab/repair/feedback.py` and `src/agentlab/repair/runner.py`, which runs a project's tests through lesson 17.2's `run_python`. The tests are in `tests/test_repair_feedback.py`. From `examples/agent-engineering/`, run `uv run --frozen python -m unittest tests.test_repair_feedback -v`. Expect `Ran 13 tests` and `OK`. The run takes a few seconds, because every case starts a real subprocess, and the infinite-loop case waits for a one-second CPU limit.

The cases cover each kind of signal from the list above with the same planted bug: the original module fails with an assertion at line 9 of `test_pricing.py`, a one-line fix passes all three tests, and variants produce a syntax error, a `TypeError` inside `line_total`, a CPU-limit kill and a missing module. `ExitCodeZeroIsNotAPass` checks that a module calling `sys.exit(0)` at import leaves exit code 0 and is still `incomplete`, and that three skips are not a pass.

To watch a test catch a real regression, change the line `return "repair"  # whatever the critic said` in `next_step` to `return "accept" if critic == "approve" else "repair"`. `test_a_critic_approval_cannot_turn_a_failing_test_into_acceptance` fails: a reviewer's approval now ships a patch that leaves ten boxes at USD 120.00. Restore the line before moving on.
