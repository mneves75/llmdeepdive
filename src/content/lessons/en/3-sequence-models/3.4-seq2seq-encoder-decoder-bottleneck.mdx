Translate a forty-word German sentence into English. The words do not appear in the same order, one language marks a distinction the other does not, and the correct English article for a noun near the end depends on a case ending near the beginning. Both sequences vary in length, and their lengths differ from each other. What architecture handles that?

## How an encoder and a decoder split the job

The 2014 answer, called **seq2seq** (sequence to sequence), separates the job in two. An **encoder** reads the source and builds a representation of it. A **decoder** generates the target one token at a time, conditioned on that representation and on what it has already produced; generating each token from the previous ones is what makes it autoregressive. The pattern covers far more than translation, including transcription, summarization, and structured generation, and the encoder-decoder split remains one of the field's durable ideas.

In the recurrent version, both halves are recurrent networks like those of [lesson 3.3](/lessons/3-sequence-models/3.3-lstm-gru-gates/). The encoder updates a hidden state across every source token. Its final state, or a transformation of it, becomes the fixed representation of the whole source. The decoder starts from that representation, consumes a beginning-of-sequence token, and predicts a probability distribution over the first target token. It feeds its choice back in and repeats until it produces an end token. Source and target lengths need not match. The model learns alignment, which source words correspond to which target words, only indirectly, through the training objective.

## How it is trained and how it generates

Training scores every target position with cross-entropy, the loss that measures how much probability the model gave the correct token ([lesson 2.4](/lessons/2-neural-network-fundamentals/2.4-loss-functions-cross-entropy/)). Masks exclude padding from that loss. The inputs and labels are offset by one position. For the target "I see you", the decoder input is the start token followed by the target tokens, `<start> I see you`, and the labels are the target followed by its end marker, `I see you <end>`. At each position, the label is the token the decoder should produce next.

**Teacher forcing**, from [lesson 3.1](/lessons/3-sequence-models/3.1-modelling-sequences/), supplies the true previous target during training. That stabilizes optimization and lets all decoder inputs be prepared in advance. At inference the true continuation is unavailable, so the decoder conditions on its own choices, and one early error changes every later input. Beam search (keeping several candidate continuations at each step and returning the highest-scoring complete one it found) and sampling (drawing each token at random according to its probability) change how that space is explored. They cannot restore source information that never made it into the representation.

## Where the whole source has to fit

That brings us to the interface itself. Look at where the entire source has to fit: one vector, produced before decoding begins, unchanged for the rest of the generation. Everything the decoder will ever need about the source must be inside it: every name, every negation, every number, the order of clauses. This is the **fixed-vector bottleneck**. It fails in two separate ways that are worth keeping apart, because they have different symptoms and only one has an obvious fix.

The first failure is capacity, and lesson 3.1 already showed how to count it. A bounded vector holds a bounded number of bits, and a long or information-dense source has more. Something is lost, and the model chooses what to lose without knowing what the decoder will ask for.

## Why the earliest source tokens are hard to train

The second failure is credit assignment, and it is easy to miss. Trace the route from an early source token to a late target loss. The gradient must travel through every remaining encoder step to reach the final state, and then through every decoder step to reach the loss. There is no other path, because the final state is the only channel.

For a forty-token source and a forty-five-token target, that is about eighty-five recurrent transitions. Apply lesson 3.3's arithmetic directly, where each step keeps a fraction of the signal (the retention factor). At a per-step retention of $0.99$ the surviving factor is $0.99^{85}\approx0.43$, which is fine. At $0.95$ it is $0.95^{85}\approx0.013$, and the first source token is effectively untrainable against a late target error. Gated cells stretched this distance; they did not remove it.

## Fixes that helped but kept the interface

The field genuinely took the following wrong turn before finding the real answer. Quality degrades on long sources, so you widen the encoder state, because a larger summary vector should hold more. It helps a little, it costs parameters, and the degradation curve keeps its shape. Then you try a bidirectional encoder, which reads the source in both directions and does improve the representations. Then stacked layers. Then, in one memorable early result, reversing the order of the source tokens. That shortens the distance from the first source words to the first target words, and it measurably improved translation.

Every one of these is a real improvement, and every one leaves the interface intact: one summary, computed once, serving all output steps. Reversal in particular gives the problem away. It improves results by shuffling *which* dependencies are short, which only makes sense if path length is the constraint that binds.

:::warning
The most common misconception is that the bottleneck is about vector size, and that a big enough summary would have worked. It is about the *interface*. Even an enormous fixed vector must be computed before the decoder knows which target word it is about to produce, so it cannot be specialized to that step. The fix is not a bigger card. It is permission to look back at the notes, which is what [lesson 3.5](/lessons/3-sequence-models/3.5-bahdanau-attention/) grants.
:::

## What survived of the encoder-decoder design

The modular separation the design introduced was still worth keeping. The encoder builds representations of the observed input, and the decoder models the target's history and generates. But separation guarantees nothing about faithfulness. A strong decoder can emit fluent, grammatical target-language text that omits or invents source content, which is exactly the failure a fixed bottleneck encourages. Evaluation therefore needs adequacy checks (does the output say what the source said?) and error analysis of omissions, repetitions, and entity substitutions. Fluency and a single aggregate overlap score are not enough.

:::insight
Decoder-only models dominate today, so it is tempting to file the encoder-decoder split as obsolete. It is not. Qwen3.8-27B is a decoder-only language model, but it is also multimodal, and images enter through a separate vision encoder: 27 layers with their own hidden width of 1152. Its output is projected to the 5120 dimensions of the language model's residual stream, the vector each token carries from layer to layer (Qwen3.8-27B Model Card, 2026). That is an encoder feeding a decoder. The decisive difference from 2014 is what it feeds. It is not one summary vector but a whole set of patch representations, one per small square region of the image, placed into the shared sequence where every later step can address any of them individually. The encoder-decoder idea survived; the fixed-vector interface did not. [Lesson 4.17](/lessons/4-transformer/4.17-multimodal-vision-encoder/) examines the vision tower in detail.
:::

A clean bottleneck experiment holds target complexity fixed while varying source length in two ways: adding relevant detail, and adding irrelevant filler. If quality falls only when relevant details become numerous or distant, the compression interface is implicated. If irrelevant padding causes equal collapse, suspect masking or optimization instead. Inspect the error types rather than the aggregate score, because the whole point is the difference between a decoder that is fluent and a decoder that is informed.
