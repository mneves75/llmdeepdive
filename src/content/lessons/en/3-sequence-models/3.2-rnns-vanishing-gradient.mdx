[Lesson 3.1](/lessons/3-sequence-models/3.1-modelling-sequences/) posed the state question and sketched two extreme answers. This lesson takes the fixed-size answer seriously and finds out exactly why it lost the 2017 argument, the year the Transformer made attention the default. Then it reports something surprising: the design that lost now runs in three quarters of the layers of this course's model.

## What a recurrent network computes

A **recurrent neural network** (RNN) is the minimal implementation of a bounded carried state. In words: the new state is a squashed mix of the old state and the current token.

Watch one step with a state that is a single number. Say the old state is 0.5, the current token contributes 1.0, and the network weights the old state by 0.8 and the token by 0.6, with no offset. The mix is 0.8 × 0.5 + 0.6 × 1.0 = 1.0. The squashing function, tanh (described below), turns 1.0 into about 0.76, and 0.76 is the new state. The next token repeats the same step starting from 0.76. A real RNN does exactly this with vectors and matrices instead of single numbers. In symbols:

$$
h_t=\phi(W_{hh}h_{t-1}+W_{xh}x_t+b),\qquad y_t=W_{hy}h_t+c.
$$

$h_{t-1}$ is the old state and $x_t$ is the current token's vector (its embedding, the list of numbers that stands for the token; [lesson 1.5](/lessons/1-text-to-tensors/1.5-embeddings-meaning-as-geometry/)). The matrices $W_{hh}$ and $W_{xh}$ mix them, $b$ is a learned offset (a bias), and $\phi$ is a nonlinearity such as $\tanh$, which squashes every number into the range between −1 and 1 ([lesson 2.3](/lessons/2-neural-network-fundamentals/2.3-activation-functions/)). The second equation reads an output $y_t$ off the state.

One transition, reused at every position. Read it as a sequence *mixer*: information from position 12 reaches position 40,000 only by surviving inside $h$ through 39,988 applications of the same function. Memory is constant, work per token is constant, and nothing is stored per position. Lesson 3.1's arithmetic already gave the first price, the bounded channel. This lesson is about the second price, which turned out to be worse.

## Why a long sequence is a very deep network

Unroll the equations, writing out one copy of the transition per position, and something important becomes visible: an RNN over a sequence of length $T$ *is* a network of depth $T$ whose layers share parameters. Sequence time and network depth are the same axis. Everything [lesson 2.8](/lessons/2-neural-network-fundamentals/2.8-initialization-normalization-residuals/) said about scale compounding across 64 layers applies here across 40,000 steps.

Training needs to learn that an early token caused a late error. It does so with **backpropagation through time**: unroll the graph, apply ordinary backpropagation ([lesson 2.5](/lessons/2-neural-network-fundamentals/2.5-backpropagation/)), and add up the gradient contributions from every use of the shared matrices. A gradient tells each parameter which direction to move, and how strongly, to reduce the loss ([lesson 0.6](/lessons/0-orientation-and-foundations/0.6-derivatives-gradients/)). By the chain rule, the derivative from state $h_T$ back to state $h_k$ contains one **Jacobian** per intervening step, multiplied together. A Jacobian is the matrix of local sensitivities: entry $(i, j)$ says how much coordinate $i$ of the next state moves when coordinate $j$ of the previous state moves a little.

## Why the gradient vanishes or explodes

Put numbers on it, in the simplest possible setting. Take a scalar recurrence $h_t=\tanh(w\,h_{t-1}+x_t)$, where the state is a single number. Each step contributes a factor of $w\cdot\tanh'(\cdot)$, the weight times the slope of $\tanh$ at that point. The slope $\tanh'$ is at most one, so the factor is at most $|w|$.

- Set $w=0.5$ and look across 50 steps: the product is at most $0.5^{50}\approx8.9\times10^{-16}$. That value remains representable in bf16 (the 16-bit format from lesson 3.1), whose exponent range matches float32. But it is an extremely small relative learning signal, and it can be overwhelmed when accumulated with much larger contributions. The early state receives almost no usable information about how it should change to reduce a loss fifty steps later. This is the **vanishing-gradient** problem.
- Set $w=1.5$ instead. The product reaches $1.5^{50}\approx6.4\times10^{8}$, so an update can become large enough to destabilize the run. These are **exploding gradients**.

Between these lies a narrow band, and $\tanh$ makes it narrower still. A unit is **saturated** when its input is far from zero, so its output sits near −1 or 1 and its slope is near zero. A saturated unit drags the product down even when $w$ is well chosen.

Note carefully what has and has not failed. The *forward* state may still carry usable information about the distant past. What breaks is credit assignment: training cannot discover which early computation to change. That is why the problem is invisible in a diagram of the forward pass and fatal in practice.

## What gradient clipping fixes, and what it cannot

Nearly everyone meeting these two failures for the first time takes the same wrong turn. Training explodes, you add gradient clipping, the run stabilizes, and you conclude the gradient problem is handled. It is not.

**Gradient clipping** rescales a gradient whose norm (its overall length as a vector) exceeds a threshold. It acts *after* differentiation, on the magnitude. With standard norm clipping, the scale factor is capped at one: large gradients shrink, while small gradients are left unchanged. That controls explosion, and it is standard practice for good reason. It does nothing for vanishing, because it cannot reconstruct information already attenuated by the long Jacobian product.

A diagnostic separates the two. Run a synthetic task with a single relevant marker placed at increasing distances from the prediction. Plot both accuracy and the gradient norm at the marker against distance. If the curve collapses toward chance with clipping enabled, distant credit was never restored, and no amount of clipping threshold tuning will change that.

## What does repair the vanishing product

Mitigations that address vanishing attack the product itself rather than its output:

- **Orthogonal initialization** starts the recurrent matrix as an orthogonal matrix (a rotation or reflection, which preserves vector lengths), so the recurrent Jacobian is close to norm-preserving at the start.
- **Truncated backpropagation** shortens the unrolled window. That saves memory and compute, but it explicitly caps how far credit can travel. This is a real limitation that belongs in the reported model, not a free optimization.
- **Additive state paths**, which [lesson 3.3](/lessons/3-sequence-models/3.3-lstm-gru-gates/) builds with gates, let a component travel across steps without passing through a full nonlinear transformation each time.
- **Attention**, arriving in [lesson 3.5](/lessons/3-sequence-models/3.5-bahdanau-attention/), sidesteps the chain entirely by creating a direct edge between distant positions.

Attention won, and it won on two counts at once. It removed the long product from the gradient path. And it made training parallel across positions, since every position's representation can be computed at the same time instead of waiting for its predecessor. Sequential execution was arguably the more decisive defeat: a design that cannot keep a modern accelerator (a GPU or similar chip) busy during training loses regardless of its other merits.

## Why recurrence came back

:::warning
The most common misconception is that this makes recurrence a historical curiosity, a chapter you read before the real material. That is wrong as a matter of current fact. Qwen3.8-27B, from the Qwen3.8 family announced in August 2026, builds 48 of its 64 layers as Gated DeltaNet. Those layers carry a fixed-size recurrent state and cache nothing per token. The model keeps full attention in only 16 layers, one in every four (Qwen3.8-27B Model Card, 2026). Three quarters of a frontier model is recurrent. What lost in 2017 was not the fixed-state idea. It was the naive vector state, the multiplicative-only transition, and the sequential training loop.
:::

:::insight
Each of those three defeats got its own answer, and the rest of this track is that answer. Lesson 3.3 replaces the raw multiplicative transition with learned gates and an additive state path, so a component can persist without being re-multiplied at every step. [Lesson 3.6](/lessons/3-sequence-models/3.6-linear-attention-fast-weights/) replaces the vector state with a *matrix* of associations. It shows that the resulting update is associative, which makes the recurrence parallelizable during training and removes the last structural objection. It also replaces the additive write with an error-correcting one, so stale associations can be reduced rather than only piled on top of each other. [Lesson 4.15](/lessons/4-transformer/4.15-gated-deltanet/) assembles the result. Read the rest of this track as a repair job on the design you just watched fail.
:::

The arithmetic that makes the repair worth doing is the one from lesson 3.1. A fixed-size state costs the same at token one and at token 262,144. In Qwen3.8-27B the recurrent layers hold roughly 144 MiB of reference float32 state in total, flat in sequence length. The attention layers' stored keys and values, the KV cache, reach 16 GiB at full context, as [lesson 7.2](/lessons/7-inference-and-efficiency/7.2-the-kv-cache/) derives. That gap is why anyone bothered to fix the RNN, and it is worth carrying into the next four lessons.
