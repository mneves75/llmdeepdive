A model is reading a document and has arrived at token 40,000. A token is the unit a model reads, usually a word or a piece of one; [lesson 1.2](/lessons/1-text-to-tensors/1.2-tokenization-i/) shows how text is cut into them. To predict token 40,001 the model may need something that happened at token 12, or at token 39,999, or nothing at all. The architecture cannot know in advance which. So it must decide, once and for all, what it is allowed to carry forward from everything it has already read.

## The one question every sequence model answers

What a model carries forward is called its **state**: the numbers it keeps about the tokens it has already read, the way a loop keeps variables between iterations. Some tasks need very little state. To check whether a line of code has balanced parentheses, a program reading one character at a time only needs one integer, the count of parentheses still open. Other tasks need much more. To answer "which name appeared on line 3?" at line 500, something about line 3 must still be stored.

That gives the question this entire track turns on: **how much state may a model carry between tokens?** Asking "which architecture is best" hides the trade. Every design in tracks 3 and 4 is a different answer to the state question, and so is the hybrid layout of this course's specimen, Qwen3.8-27B, the model the course uses as its running example. Each answer buys one thing and pays for it with another.

Two extreme answers bracket the space.

## Answer one: a fixed-size state

The first answer says the state is a vector of fixed size. At every position the model computes a new state from the old state and the current token, and the old one is discarded. The parentheses counter is the smallest example: the new count is the old count, plus one for "(" and minus one for ")". Written in general:

$$
h_t=f(x_t,h_{t-1};\theta),\qquad y_t=g(h_t;\theta_y).
$$

Here $x_t$ is the token at position $t$, $h_t$ is the state after reading it, $f$ is the update rule, and $g$ turns the state into an output $y_t$, such as a prediction of the next token. The same parameters $\theta$ (the learned numbers inside $f$) act at every position, which is what lets one model handle any length. Memory is constant, work per token is constant, and token 40,000 costs exactly what token 1 cost. [Lesson 3.2](/lessons/3-sequence-models/3.2-rnns-vanishing-gradient/) develops this design.

## Answer two: a record for every position

The second answer says: keep one record for every position. Each record holds a **key**, a vector describing what that position contains, used to decide whether it is relevant, and a **value**, a vector holding the content to read. When predicting, the model computes a learned score between its current need and every key, and uses those content scores to mix the records. This avoids compressing the whole past into one recurrent state, and it preserves a direct path to every stored position. But the records are learned projections and the result is a weighted blend, so exact retrieval of any one past token is not guaranteed. Memory grows with every token, and the work of consulting the store grows too. [Lesson 3.5](/lessons/3-sequence-models/3.5-bahdanau-attention/) introduces the mechanism, and track 4 builds the whole Transformer on it.

## Why a fixed state has a hard ceiling

The limit of a fixed state is arithmetic, not a vague worry about "forgetting". Here is the count.

Consider a copy task: show the model a random sequence of tokens, then a delimiter (a separator token), and require it to reproduce the sequence exactly. Take a vocabulary, the set of possible tokens, of 1000 items. Picking one item out of 1000 equally likely ones takes about ten yes/no answers, so each random token carries $\log_2 1000\approx9.97$ bits of information. Now take a state of 256 numbers stored in bf16, a 16-bit (2-byte) number format common in modern models. That is 512 bytes, or 4096 bits: an absolute upper bound on what the state can hold.

- A 100-token sequence to copy carries about 997 bits. That fits inside 4096, so the task is at least *possible*. Whether training finds the solution is a separate question.
- A 1000-token sequence carries about 9970 bits. That does not fit.

No model with this state size copies 1000 random tokens through a 512-byte channel, whatever its architecture, learning rate, dataset or training time, because the information is not there to be recovered.

:::insight
This is the same kind of argument as XOR in [lesson 2.1](/lessons/2-neural-network-fundamentals/2.1-perceptron/), where a single perceptron cannot represent XOR however long it trains. When a bounded state cannot hold what a task requires, you are looking at a representational ceiling, not an optimization problem. Real language rarely demands exact recall of ten thousand random symbols, so the practical version is subtler than the copy task. But the shape of the limit never goes away: a fixed state must decide what to forget, and it makes that decision before knowing what the future will ask for.
:::

This count prevents a classic wrong turn. A model fails on a task that needs information from far back, and the reflex is to train longer, widen the network, or blame the optimizer. Sometimes that is right. Before spending a week on it, do the counting: estimate how many bits the task requires to cross the gap, and compare that with what the carried state can physically hold. If the required information exceeds the channel, stop tuning and change the architecture. If it fits comfortably and the model still fails, you have a genuine learning problem, which lesson 3.2's vanishing gradients will explain.

## What storing everything costs

The other extreme has a cost too, and at production scale it is large: storing every position means memory that grows without bound. The stored keys and values are called the **KV cache**. [Lesson 7.2](/lessons/7-inference-and-efficiency/7.2-the-kv-cache/) works out the exact bill for Qwen3.8-27B: at its native 262,144-token context, the KV cache of a single sequence reaches 16 GiB (gibibytes; one GiB is 1024 MiB, mebibytes).

Against that, the layers of the same model that carry a fixed recurrent state instead hold roughly 144 MiB in total. That figure is for the reference float32 path, the Hugging Face Transformers implementation that keeps this state in 32-bit floats. It does not change whether the sequence is one hundred tokens or a quarter of a million (Qwen3.8-27B Model Card, 2026). Sixteen gibibytes against one hundred forty-four mebibytes, for the same sequence, inside the same model. Hold that contrast. The rest of this course keeps returning to it, and [lessons 3.6](/lessons/3-sequence-models/3.6-linear-attention-fast-weights/), [4.15](/lessons/4-transformer/4.15-gated-deltanet/) and [4.16](/lessons/4-transformer/4.16-hybrid-layouts/) explain how one model came to contain both answers at once.

## Rules that keep a sequence experiment honest

Some housekeeping is part of the problem itself. Which context is legal depends on the task. A **causal** model predicts position $t+1$ from earlier positions only, so it may not see future tokens. That boundary must be enforced during training, even though every target already sits in the file. A **bidirectional** encoder, a model that reads a complete input to build a representation of it, may read both sides when classifying a complete sentence. Using future information in an offline benchmark silently invalidates a system meant to run live. It is one of the easiest mistakes to make and the hardest to notice.

Training processes several sequences at once in a **batch**, and those sequences have different lengths. **Padding** fills the short ones with filler positions so the batch forms a rectangular tensor, and a **mask**, an array of true/false flags, marks which positions are real. Padding must not change any state, receive any attention weight, or contribute to the loss, the number training minimizes ([lesson 2.4](/lessons/2-neural-network-fundamentals/2.4-loss-functions-cross-entropy/)). A masking bug can produce excellent metrics in two ways: by leaking labels, or by averaging over easy padded positions. Either way, the metric looks wonderful throughout.

An **autoregressive** model generates one token at a time and feeds each output back in as the next input. Training such a model normally uses **teacher forcing**: at step $t$ the model receives the true previous token rather than its own sample. This lets all targets be built in parallel and stabilizes learning. At inference, when the trained model is actually used, it conditions on its own earlier choices instead, so an early error changes all later context. The mismatch is real, and the alternatives have costs of their own.

:::caveat
The most common misconception about state is that a model's advertised context length describes how much of the past it uses. It does not. A context window is an input limit: the longest sequence the implementation will accept without an error. It says nothing about whether information at position 12 measurably influences the prediction at position 40,000. Marketing and casual readings of model cards routinely conflate the two, and the gap between them is exactly what this track is about. Only a controlled probe settles it: place the required information at a known distance, vary the distance, and measure on held-out data, data the model never trained on ([lesson 2.9](/lessons/2-neural-network-fundamentals/2.9-overfitting-regularization-bitter-lesson/)).
:::

Finally, evaluation must match the structure of the task:

- Per-token accuracy can hide poor whole-sequence validity.
- Averaging loss across padded and unpadded positions differently changes the number.
- Generated sequences need decoding choices (how the next token is picked from the model's probabilities) and often have several acceptable targets.

Report directionality, context limit, truncation, masking, and how metrics aggregate.

A reliable leakage test is worth building once and keeping. Construct two examples identical up to time $t$ and different afterward. Then confirm that the causal representation at $t$ is bit-identical in evaluation mode. If it moves, future information reached it through masking, preprocessing, normalization, or target construction.
