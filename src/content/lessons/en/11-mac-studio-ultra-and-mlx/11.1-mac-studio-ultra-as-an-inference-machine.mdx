You own, or are about to buy, a Mac Studio with an M5 Ultra. Apple's page lists a chip, a GPU core count and a memory size. Only two of those decide whether a local model runs well: how much memory the GPU may use, and how fast it can read it. A third number, compute, leads the marketing and matters less than it looks. This lesson separates the three.

## The two lines that matter

| | M3 Ultra (March 2025) | M5 Ultra (2026) |
|---|---|---|
| Unified memory | 96 GB base, up to 512 GB | 96 GB base; 256 GB or 512 GB with the 80-core GPU |
| Memory bandwidth | "over 800GB/s" | 1.2 TB/s on both GPU options |

The 512 GB configuration ships in late October 2026. Apple says the new bandwidth is 50 percent higher than before, which matches the 1.5 ratio against the 800 GB/s that lesson 9.6 used. The M5 Ultra has a 64-core or an 80-core GPU and a 32-core Neural Engine, and the 256 GB and 512 GB options require the 80-core GPU. Apple's Mac Studio page says the M5 Ultra fuses two M5 Max chips into a single SoC.

Lesson 9.6 owns the method: vendor bandwidth divided by artifact size is a planning heuristic. This lesson owns the M5 Ultra quotients for the pinned Q4_K_M artifact and the bf16 checkpoint:

$$
\frac{1{,}200\ \text{GB/s}}{17.1\ \text{GB}} \approx 70.2\ \text{tokens per second}, \qquad \frac{1{,}200\ \text{GB/s}}{54\ \text{GB}} \approx 22.2\ \text{tokens per second}.
$$

Both are heuristics built from a vendor figure and a file size. Real decode reads cache and state too, and no system reaches peak bandwidth. Measure before you quote them.

## What 96, 256 and 512 GB buy

All three tiers hold the 54 GB bf16 checkpoint. Capacity decides what else shares the pool, and it has no term in the decode quotient above. Lesson 9.3 sizes one 8,192-token sequence at 656 MiB, cache plus DeltaNet state. Every extra 100 GiB the GPU may use is room for about 156 more of them, since 102,400 MiB divided by 656 MiB is 156. Larger tiers therefore buy concurrency, longer contexts, or models that do not fit a smaller tier. They do not buy faster single-stream decode.

## How much of that memory the GPU may use

Installed memory is the ceiling, not the budget. macOS caps the memory the GPU may keep wired, and MLX documents that cap as `max_recommended_working_set_size`. Read it, and read the sysctl behind it, before you plan:

```python
import mlx.core as mx

info = mx.device_info()
gib = 2**30
print("memory_size", round(info["memory_size"] / gib, 1), "GiB")
print("max_recommended_working_set_size",
      round(info["max_recommended_working_set_size"] / gib, 1), "GiB")
```

```bash
sysctl iogpu.wired_limit_mb
```

The MLX docs say a wired limit set above the system limit is an error. To raise the system limit they give `sudo sysctl iogpu.wired_limit_mb=N`, and the mlx-lm README adds that N should be larger than the model in megabytes but smaller than the machine's memory. That is a system change. This lesson quotes it from the pinned sources and did not run it. Read the value again after a reboot instead of assuming it stayed. On the Mac used to check this lesson the sysctl read 0, and the MLX call still reported a limit, so read both.

You rarely need to set MLX's own wired limit. `mlx_lm.server` sets it to the recommended size at start-up. `mlx_lm.generate` sets it for the run and prints a warning when the model needs more than 90 percent of that size.

## Compute is the third number

Apple's newsroom footnote for "up to 4.3x the peak AI compute performance of M3 Ultra" says only that Apple tested in July 2026. It names no model and no metric, and it is a peak figure. The Mac Studio page is more specific for its other AI headline: "up to 9.8x faster AI performance than M1 Ultra" is time to first token with an 8K-token prompt on a 14-billion-parameter 4-bit model in LM Studio. That is a prefill metric. Apple's own research post explains where such a gain lands. In MLX tests on a MacBook Pro with M5 against one with M4, running Qwen3 and gpt-oss models, the first token was compute-bound and up to four times faster with the Neural Accelerators. Later tokens were bound by memory bandwidth and gained 19 to 27 percent for 28 percent more bandwidth. Prefill is compute, decode is bandwidth, as lesson 7.3 taught.

That gives the classic wrong turn: reading 4.3 times the compute as 4.3 times faster chat. A chat reply is one prefill plus many decode steps. Bandwidth rose by 1.5, so decode can gain about that much at best. A long document or an agent that re-reads a large context spends most of its wait in prefill, and there the new compute can pay off. Measure the two phases apart, on a prompt long enough to be prefill. A 12-token prompt measures start-up, not prefill.

```bash
yes 'Tides rise and fall twice a day.' | head -n 300 > long.txt
mlx_lm.generate --model mlx-community/Qwen3-4B-Instruct-2507-4bit --prompt - --max-tokens 64 < long.txt
```

The command prints a `Prompt:` line for prefill and a `Generation:` line for decode, plus peak memory. The small model stands in for the course model so that you can check the procedure anywhere. Record both lines for your own machine and do not quote another machine's.

:::warning
Do not set the wired limit at the machine's total memory. The README says N must stay below it, and it gives no safe margin. The operating system, your other apps and Metal buffers share the pool, and a model pushed to the edge starts to swap. Leave a margin on purpose and watch swap during a long run.
:::

:::caveat
Every Apple figure here is a vendor figure from Apple's July 2026 tests. The newsroom footnote for the 4.3x compute claim names no model or metric. The product-page footnotes for the 9.8x claim and for the 3x clustering claim, which lesson 11.5 covers, do name their tests, and both are prefill-style jobs. The M5 versus M4 numbers come from a different chip and from Qwen3 and gpt-oss models, not from Qwen3.8-27B. Treat each as a pointer to what to measure.
:::

The durable idea is that one machine has three independent numbers. Capacity says what fits, bandwidth says how fast one stream decodes, and compute says how fast a long prompt is read. Lesson 11.2 goes inside MLX to see how it spends all three.
