A Mac Studio on a desk is a fine inference server for a team, and two programs turn it into one. `mlx_lm.server` ships with mlx-lm, from Apple's ml-explore project. `mlx-serve` is a separate project by David Dalcu, written in the Zig programming language and pinned here at v26.10.1. An unrelated project, raspoli/mlx-serve, shares the name, so check the owner before you download. Both speak an OpenAI-style API: they implement a subset of OpenAI's text-completion endpoints and parameters, so client code written for those can point at your Mac. They differ in three ways: what they batch, what they cache, and who can reach them by default.

## mlx_lm.server at 0.32.0

Who can reach a server depends on the network address it binds to, that is, listens on. Loopback, 127.0.0.1, is reachable only from the same Mac. Start the server on loopback, then query it from a second terminal:

```bash
mlx_lm.server --model mlx-community/Qwen3-4B-Instruct-2507-4bit --host 127.0.0.1 --port 8080
```

```bash
curl -s http://127.0.0.1:8080/health
curl -s http://127.0.0.1:8080/v1/chat/completions -H 'Content-Type: application/json' -d '{"messages":[{"role":"system","content":"You are a terse assistant for the fictional Harbor service. Retry budget is three attempts. Delay starts at 200 ms and doubles."},{"role":"user","content":"How many attempts?"}],"max_tokens":24,"temperature":0}'
```

The endpoints are `/v1/chat/completions` (also `/chat/completions`), `/v1/completions`, `/v1/models` and `/health`.

**Prompt reuse.** When a new prompt starts with the same tokens as an earlier one, the server can reuse the saved KV cache of that start (the stored keys and values of [lesson 7.2](/lessons/7-inference-and-efficiency/7.2-the-kv-cache/)) instead of reading those tokens again. Run the chat request twice to see it. The first reply carries `"cached_tokens": 0` in `usage.prompt_tokens_details`. The second repeats the prompt and reports 44 of its 45 tokens cached. That field is how you see prompt reuse from outside. Inside, the server keeps an LRU of distinct caches (least recently used: when it is full, the cache untouched the longest is dropped). It holds 10 by default, capped in bytes by `--prompt-cache-bytes`, and is searched for the nearest cached token prefix.

**Batching.** Batching runs several requests through the model in the same step, and continuous batching ([lesson 7.8](/lessons/7-inference-and-efficiency/7.8-pagedattention-and-continuous-batching/)) lets requests join and leave between steps. Batching is on by default in mlx_lm.server, with `--decode-concurrency 32` and `--prompt-concurrency 8`. A request is batched only if all four of these hold:

- the server has no draft model (the small helper model of speculative decoding, [lesson 7.5](/lessons/7-inference-and-efficiency/7.5-beam-search-speculative-decoding-and-medusa/));
- every cache type can merge into one batched cache;
- the request sets no `seed` (a fixed starting value for random sampling);
- `--kv-bits` is unset.

Otherwise the server drains the batch and serves the request alone. The KV quantization of [lesson 11.3](/lessons/11-mac-studio-ultra-and-mlx/11.3-mlx-lm-in-practice/) therefore trades batching for memory: at this version a server started with `--kv-bits` handles one request at a time.

## mlx-serve v26.10.1

mlx-serve is one native binary that serves MLX models and, through an embedded llama.cpp, GGUF files (llama.cpp's model format, [lesson 8.7](/lessons/8-building-and-serving-stacks/8.7-llama-cpp-and-gguf/)). It speaks the OpenAI, Anthropic and Ollama wire formats on one port. Its `LICENSE` is MIT for its own code, with third-party components under their own terms. Download the release, check the hash against the digest GitHub shows, and start it on loopback:

```bash
gh release download v26.10.1 --repo ddalcu/mlx-serve --pattern 'mlx-serve-bin-macos-arm64.tar.gz'
shasum -a 256 mlx-serve-bin-macos-arm64.tar.gz
tar -xzf mlx-serve-bin-macos-arm64.tar.gz
./mlx-serve-macos-arm64/mlx-serve --version
./mlx-serve-macos-arm64/mlx-serve --model q4-g64 --serve --host 127.0.0.1 --port 11234 --max-concurrent 4
```

In a second terminal, ask for an Anthropic-style reply:

```bash
curl -s http://127.0.0.1:11234/v1/messages -H 'Content-Type: application/json' -H 'anthropic-version: 2023-06-01' -d '{"model":"mlx-serve","max_tokens":16,"messages":[{"role":"user","content":"Name one planet."}]}'
```

The `--version` line reports the MLX it embeds, 0.32.3 for this release. The directory `q4-g64` is the MLX model that lesson 11.3 converted. Continuous batching is off until you pass `--max-concurrent N`, and its prefix cache is on by default. Its responses add a `timings` object, which is the server's own clock.

## How to time two servers on the same clock

**Time to first token** is the wait from sending a request to receiving the first piece of reply text. It is tempting to compare two servers by one such number taken from two different clocks, for example mlx-serve's own `timings` against a client-side stopwatch on the other server. Use one clock for both instead: the client's.

Time to first token is also not the first byte. A streamed reply arrives as SSE (server-sent events): the server keeps one HTTP response open and writes a line for each piece, or chunk. `mlx_lm.server` writes SSE comment lines such as `: keepalive 10/11` while it processes the prompt, and both servers sent bytes before any text. So stop the clock at the first chunk that carries text:

```python
import json, sys, time, urllib.request

def measure(base, prompt, max_tokens=64):
    body = json.dumps({
        "messages": [{"role": "user", "content": prompt}],
        "max_tokens": max_tokens, "temperature": 0, "stream": True,
        "stream_options": {"include_usage": True},
    }).encode()
    req = urllib.request.Request(base + "/v1/chat/completions", body,
                                 {"Content-Type": "application/json"})
    t0 = time.perf_counter()
    first_byte = first_text = last_text = usage = None
    with urllib.request.urlopen(req) as resp:
        for raw in resp:
            now = time.perf_counter() - t0
            first_byte = now if first_byte is None else first_byte
            line = raw.decode().strip()
            if not line.startswith("data: ") or line == "data: [DONE]":
                continue
            chunk = json.loads(line[6:])
            usage = chunk.get("usage") or usage
            for choice in chunk.get("choices", []):
                if choice.get("delta", {}).get("content"):
                    first_text = now if first_text is None else first_text
                    last_text = now
    if usage is None or first_text is None or last_text == first_text:
        return {"first_byte_s": first_byte, "ttft_s": first_text,
                "decode_tok_s": None,
                "cached": (usage or {}).get("prompt_tokens_details", {}).get("cached_tokens"),
                "note": "decode rate unavailable: need at least two text chunks and a usage block"}
    n = (usage or {}).get("completion_tokens")
    if not n or n < 2:
        return {"first_byte_s": first_byte, "ttft_s": first_text,
                "decode_tok_s": None,
                "cached": (usage or {}).get("prompt_tokens_details", {}).get("cached_tokens"),
                "note": "decode rate unavailable: need at least two completion tokens"}
    return {"first_byte_s": first_byte, "ttft_s": first_text,
            "decode_tok_s": (n - 1) / (last_text - first_text),
            "cached": (usage or {}).get("prompt_tokens_details", {}).get("cached_tokens")}

print(measure(sys.argv[1], sys.argv[2]))
```

Run `python ttft.py http://127.0.0.1:8080 "Write two sentences about harbors."` against each server. Decode rate counts tokens after the first, from the usage block, over the time between the first and last text. For a fair comparison:

- Use the same weights and prompt at temperature 0.
- Record `cached`, so cold runs (nothing cached) and warm runs stay apart.
- Repeat, and report the spread, not one run.
- Match the settings that change the work. That means `--decode-concurrency` against `--max-concurrent`, and mlx-serve's speculative decoding: its Prompt Lookup Decoding, which guesses upcoming tokens from text already in the prompt, is on by default, and `--no-pld` turns it off.

Do not quote numbers from another Mac or another model.

:::warning
Neither server is a hardened internet service. `mlx_lm.server` documents that it implements only basic security checks. It has no authentication. `--allowed-origins`, the list of websites whose scripts a browser lets read the server's responses (a browser rule called CORS, not authentication: it stops nothing that is not a browser), defaults to `*`, meaning any site. And a request's `model` field can name another model for the server to load. mlx-serve defaults to `0.0.0.0`, which means every network the Mac is on, in its help text and in `main.zig`, although its `SECURITY.md` says 127.0.0.1 is the default. Its `--api-key` exempts loopback unless you add `--api-key-strict`, and `--lan-share` advertises models over Bonjour, Apple's local-network discovery. Always pass `--host 127.0.0.1`, and put a real proxy with authentication in front of anything shared.
:::

:::caveat
mlx-serve's README table lists mlx-lm as having no OpenAI-compatible API and no continuous batching. The pinned mlx-lm source has both. Read the pinned source, not a comparison table, including this lesson's. The throughput claims in that README were not reproduced here. The servers were run only to confirm the commands and response shapes above.
:::
