Deterministic code (fixed programmatic rules) catches broken JSON (JavaScript Object Notation, a structured text format for data fields), missing citation IDs, and stale policy tags, yet fixed code cannot read a paragraph and decide whether a claim genuinely follows from chunk `c2`. That meaning-based gap is where *LLM-as-a-judge*—one large language model (LLM) grading another model's trace against a narrow rubric—enters the pipeline. As [lesson 23.4](/lessons/23-agent-evaluation-and-ci/23.4-calibrate-the-graders/) established for agent graders, an uncalibrated judge is worse than no judge because it shows reassuring green dashboards while rubber-stamping (approving indiscriminately) real failures. This lesson contrasts a balanced judge against an imbalanced trap using exact confusion-matrix arithmetic (a 2×2 table comparing judge verdicts to human labels), then unpacks the judge biases you must control in production.

## Why raw agreement hides a rubber-stamp judge

Compare two binary judges (`pass` vs `fail`) audited on 100 human-labeled traces drawn from the failure taxonomy of [lesson 29.1](/lessons/29-llm-and-rag-evaluations/29.1-error-analysis-and-failure-taxonomies/). Each case falls into one of four confusion-matrix counts: a *true positive* (`tp`) when both judge and human pass it, a *false positive* (`fp`) when the judge passes a human-labeled failure, a *false negative* (`fn`) when the judge fails a human-labeled pass, and a *true negative* (`tn`) when both fail it.

First, inspect a **balanced judge** on 100 cases containing 48 human passes and 52 human failures: true positives $\text{tp} = 42$, false positives $\text{fp} = 8$, false negatives $\text{fn} = 6$, and true negatives $\text{tn} = 44$.

- **Observed agreement** $p_o = (42 + 44) / 100 = 0.86$ (86%).
- **Marginal rates** (each side's overall pass and fail share on its own): the judge predicts pass on $(42 + 8)/100 = 0.50$ and fail on $0.50$; humans label pass on $(42 + 6)/100 = 0.48$ and fail on $0.52$.
- **Expected chance agreement** $p_e = 0.50 \times 0.48 + 0.50 \times 0.52 = 0.240 + 0.260 = 0.500$ (50.0%).
- **Cohen's kappa** (Cohen, 1960) measures agreement *beyond chance*:
  $$
  \kappa = \frac{p_o - p_e}{1 - p_e} = \frac{0.86 - 0.50}{1 - 0.50} = \frac{0.36}{0.50} = 0.720.
  $$
- **Classification balance** (how many judge passes are truly valid, how many true passes the judge catches, and their combined harmonic mean): $\text{Precision} = 42 / (42 + 8) = 84.0\%$, $\text{Recall} = 42 / (42 + 6) = 87.5\%$, and $F_1 = 2 \times 0.840 \times 0.875 / (0.840 + 0.875) = 0.857$.

Now inspect the **imbalanced rubber-stamp trap** on 100 production traces where 94 pass and only 6 fail: $\text{tp} = 90$, $\text{fp} = 5$, $\text{fn} = 4$, $\text{tn} = 1$.

- **Observed agreement** $p_o = (90 + 1) / 100 = 0.91$ (91%)—five points *higher* than the balanced judge!
- **Marginal rates:** the judge predicts pass on $95/100 = 0.95$ and fail on $0.05$; humans label pass on $94/100 = 0.94$ and fail on $0.06$.
- **Expected chance agreement** $p_e = 0.95 \times 0.94 + 0.05 \times 0.06 = 0.893 + 0.003 = 0.896$ (89.6%).
- **Cohen's kappa** exposes the collapse immediately:
  $$
  \kappa = \frac{0.91 - 0.896}{1 - 0.896} = \frac{0.014}{0.104} = 0.135.
  $$

Despite boasting 91% raw agreement, the rubber-stamp judge caught only 1 of the 6 true failures (`tn = 1`, `fp = 5`). Any automated release gate (the pre-ship check that blocks broken changes) relying on raw agreement above 90% would deploy a blind grader to production.

## Three systematic biases in LLM judges

Zheng et al. (2023) studied frontier models acting as judges on MT-Bench and Chatbot Arena and documented three recurring biases that distort automated scoring if left uncontrolled:

- **Position bias:** in pairwise comparisons (putting two answers side by side and asking `"Is Answer A or Answer B better?"`), judges systematically favor whichever answer sits in the first (or sometimes second) slot, especially when quality is close. Mitigation: run every pairwise item twice with A and B swapped, and count a win only when both orders agree.
- **Verbosity bias:** judges reward longer, more elaborately formatted responses even when extra sentences add zero factual support or slip in unsupported filler. Mitigation: grade narrow binary rules (`"Does every claim appear in the cited chunks?"`) rather than overall quality, and include concise passing examples plus verbose failing examples in calibration.
- **Self-enhancement bias:** models tend to assign higher scores to outputs generated by their own model family than to equally strong outputs from another family. Mitigation: separate generator and judge model families whenever possible, and calibrate strictly against human ground truth—never against another model's votes.

## Building a calibration loop that does not overfit

A disciplined judge-calibration workflow mirrors supervised machine learning (training and testing a system against labeled examples) so the judge prompt does not overfit (memorize the tuning examples instead of learning the general rule):

1. **Balance the calibration sample:** do not pull 100 random traces when production fails only 4% of the time; oversample (deliberately gather more of) known failures and near-misses so the human-labeled set carries roughly 40% to 50% negatives across every taxonomy bucket.
2. **Measure human-to-human agreement first:** have two domain reviewers label an overlapping slice (for instance, 30 items). If human inter-annotator kappa (agreement between the two people beyond chance) is only 0.45, rewrite the rubric before blaming the LLM—no model can match an ambiguous standard.
3. **Split dev and held-out test sets:** inspect errors on a development split to sharpen rubric wording and add 2 to 3 boundary few-shot examples (worked examples placed inside the judge prompt), then report final $\kappa$, precision, and recall on an untouched held-out split.
4. **Require structured verdicts with short rationales:** ask the judge for a concise evidence quote and a binary `PASS` or `FAIL` field via structured output (forcing the reply into fixed named fields), treating malformed replies as failures rather than unnoticed passes.

:::warning
Re-calibrate your judge whenever you change the judge model version, update the rubric, or shift the underlying product domain. A judge that reached $\kappa = 0.720$ on refund policy traces can drift without triggering alarms when applied to technical troubleshooting logs.
:::
