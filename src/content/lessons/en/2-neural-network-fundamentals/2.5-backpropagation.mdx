[Lesson 2.4](/lessons/2-neural-network-fundamentals/2.4-loss-functions-cross-entropy/) produced a single number: the loss. To improve the model you need to know, for every parameter, whether nudging it up or down would make that number smaller. That is the parameter's **gradient**, the slope of the loss with respect to it ([lesson 0.6](/lessons/0-orientation-and-foundations/0.6-derivatives-gradients/)). There is an obvious way to find out. Perturb one parameter by a tiny amount, run the model again, see how the loss moved, and divide. Repeat for the next parameter.

## Why not nudge each parameter and measure?

That plan is called **finite differences**. Price it honestly, because it is the wrong turn worth walking into. A careful two-sided estimate, which nudges the parameter once up and once down, needs two forward passes (full runs of the model from input to loss) per parameter. For a small network with ten thousand parameters that is twenty thousand forward passes per gradient: slow but survivable. For Qwen3.8-27B, with roughly 27 billion parameters (Qwen3.8-27B Model Card, 2026), it is 54 billion forward passes to obtain the gradient for a *single* training step. If one forward pass took a millisecond, one step would take about twenty months. At this size, finite differences are unusable.

## How does one backward sweep get every gradient?

**Backpropagation** is what replaces it, and the gain is a change in kind. One backward sweep produces the gradient for every parameter at once, at a cost of roughly the same order as evaluating the graph. A larger model still makes both passes more expensive; the saving is that reverse mode does not require a separate evaluation for every parameter.

The mechanism is the chain rule (the derivative of a composition is the product of the derivatives of its steps) applied to a recorded graph. The **forward pass** evaluates operations in order, saving the intermediate values that derivatives will need. The **backward pass** starts at the end with $\partial L/\partial L=1$ and walks the operations in reverse. At every operation the rule is the same: **upstream gradient times local derivative**. The upstream gradient is what arrives from the operations closer to the loss; the local derivative says how this operation's output responds to its own input. Each operation only needs that local knowledge. It never needs to know anything about the rest of the network.

## A backward pass by hand

Do one by hand, using the loss from lesson 2.4. Take three logits (raw class scores) $z=(2.0,\,1.0,\,0.1)$ with the observed class being the first.

Forward: the exponentials are about $7.389$, $2.718$, and $1.105$, summing to $11.212$, so $p\approx(0.659,\,0.242,\,0.099)$ and $L=-\ln 0.659\approx0.417$.

Backward: for softmax (which turns logits into probabilities) followed by cross-entropy, the gradient with respect to the logits reduces to a strikingly simple form, $\partial L/\partial z=p-y$, where $y$ is the one-hot target (1 for the observed class, 0 elsewhere). Here that is $(0.659-1,\;0.242-0,\;0.099-0)=(-0.341,\,0.242,\,0.099)$. Read it as an instruction. The correct class carries a negative gradient, so gradient descent will raise its logit. The two wrong classes carry positive gradients in exact proportion to the probability they took, so their logits get pushed down, the more confidently wrong one hardest.

Now suppose those logits came from $z=Wh+b$ for a hidden vector $h$. The same rule continues: $\partial L/\partial b=p-y$, $\partial L/\partial W=(p-y)h^{\top}$, and $\partial L/\partial h=W^{\top}(p-y)$. That last one is the message handed to the layer below, which will apply the identical procedure with its own local derivative.

## What happens when a value feeds two paths?

Graphs branch, and branching is where implementations get subtle. If a value influences the loss along two paths, its gradient is the **sum** of the two contributions, because that is what the multivariable chain rule says. This is why autodiff frameworks (libraries such as PyTorch that compute these derivatives automatically) accumulate into gradient buffers rather than overwriting them. It is also why a training loop must zero those buffers at batch boundaries: summation is the mathematically correct default for repeated use, and only the loop knows where one batch ends.

## What does backpropagation cost at this model's scale?

:::insight
Now scale the picture to this course's model. Qwen3.8-27B stacks 64 layers, each carrying a hidden state 5120 wide per token (Qwen3.8-27B Model Card, 2026). A backward pass is a single sweep from the loss at the top down through all 64 layers. At each one it produces both the gradients for that layer's matrices and the message passed further down. The remarkable fact is that the algorithm follows the recorded graph once instead of rerunning the model separately for every parameter: one sweep, every gradient, which is the only reason models of this size exist.
:::

The bill arrives as memory rather than time. The backward pass needs values the forward pass computed, so training holds **activations** (the intermediate outputs of each layer) alive from the moment they are produced until their gradients are consumed. Multiply that by 64 layers, by the intermediate width of 17408 inside each feed-forward block, and by every token position in the batch, and activation memory rivals or exceeds parameter memory. **Gradient checkpointing** buys memory back by storing only selected boundaries and recomputing the rest during backward. It trades more compute for less memory, and [lesson 5.10](/lessons/5-pretraining-at-scale/5.10-gradient-checkpointing/) turns that lever explicitly.

## How do you tell a small gradient from a bug?

:::warning
The most common misconception is that a small or zero gradient signals a bug in differentiation. It usually does not. Backpropagation faithfully reports the derivative of the computation it was handed. An uninformative gradient is normally a fact about the model's geometry: a saturated activation, a dead unit, or products of many small local derivatives across depth. The fix then belongs to architecture, initialization, or normalization rather than to autodiff. What *is* a bug is a severed path: converting a tensor to a plain number, mutating a saved value in place, or running a region under a no-gradient context. Those produce a gradient of exactly zero or none at all, which is a different symptom from a small one.
:::

Two habits keep this honest. First, for any new custom operation, gradient-check it against finite differences on a tiny input. The method that fails at scale is perfectly good as a unit test, given sensible precision and step size, away from non-differentiable points. Second, before a long run, confirm that every parameter you expect to train has a finite, nonzero gradient after one loss. The enduring picture is a reverse flow of responsibility through a recorded graph, where purely local rules compose into global sensitivity. And the optimizer of [lesson 2.7](/lessons/2-neural-network-fundamentals/2.7-optimizers/) has not yet done anything at all.
