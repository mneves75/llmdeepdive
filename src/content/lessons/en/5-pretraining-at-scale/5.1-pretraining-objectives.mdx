You have a cluster, a corpus, and a 27-billion-parameter network. Nothing yet tells the optimizer (the algorithm that nudges the weights after each batch) what a mistake is. Before a single gradient exists, someone must write a rule that turns raw text into inputs, targets, and a loss. That rule is the **pretraining objective**. It decides two things: what each prediction is allowed to see, and which error gets corrected. Two models trained on the same corpus under different objectives practise different skills, and no amount of compute turns one skill into the other.

## What does Qwen3.8-27B learn to predict?

Start with the objective Qwen3.8-27B actually uses, because it is the simplest one and the whole course rests on it. It is **causal language modelling**: read the text left to right and, at every position, predict the next token from the tokens before it.

Take the toy sentence "the cat sat on the mat". The model receives "the cat sat on the" and is scored at every position at once: after "the" it should predict "cat", after "the cat" it should predict "sat", and so on. The targets are the inputs shifted one position to the left. In symbols, the sequence is factorized left to right: at position $i$ the model predicts $x_{i+1}$ from $x_{\le i}$. A triangular mask (the causal mask of [lesson 4.4](/lessons/4-transformer/4.4-causal-masking/)) blocks each position from seeing the future, and the shifted targets supply a loss at nearly every position. This is exactly the mini-GPT you built in [lesson 4.13](/lessons/4-transformer/4.13-build-gpt-from-scratch/), scaled up.

Each prediction is a probability distribution with one class per row of the output embedding (the matrix that turns the model's final vector into a score for every token in the vocabulary). This model's output embedding is 248,320 rows wide, and it is untied from the input embedding: the two are separate matrices. The model card and config give each of them roughly 1.271 billion parameters.

## What does a loss of 12.42 nats mean?

Work through what that vocabulary size means for the loss. The loss here is cross-entropy ([lesson 2.4](/lessons/2-neural-network-fundamentals/2.4-loss-functions-cross-entropy/)): $-\ln p(\text{correct token})$, the negative log of the probability the model gave the right answer. Take as a baseline a model that guesses uniformly, spreading its probability evenly over all 248,320 classes. It assigns each one $1/248{,}320$, so its loss is

$$
-\ln\frac{1}{248{,}320}=\ln 248{,}320\approx 12.42\ \text{nats}\approx 17.92\ \text{bits}.
$$

Nats and bits are the same quantity measured with the natural log and the base-2 log ([lesson 1.7](/lessons/1-text-to-tensors/1.7-entropy-perplexity/)). That 12.42 is the score of pure guessing.

Now run the same arithmetic backwards from a plausible value after training. Suppose a trained model reaches a mean loss of 2.0 nats. Then $e^{-2.0}\approx 0.135$ is the **geometric mean** of the probabilities it assigned to the correct next tokens: roughly one in seven as an effective probability. Uniform guessing gives $1/248{,}320\approx 0.000004$. The trained model's geometric-mean probability is about 33,000 times higher. It is not the arithmetic mean of per-token probabilities: a geometric mean is pulled down hard by the few tokens the model got badly wrong, which is exactly what an average of log-losses does.

## What does multi-token prediction add?

Two model-card facts extend the picture for this model. First, it is trained with **multi-token prediction** (MTP): alongside the next token, additional heads (small output layers on top of the network) predict tokens further ahead. Second, it is **natively multimodal**. Image and video patches are produced by the vision tower of [lesson 4.17](/lessons/4-transformer/4.17-multimodal-vision-encoder/) and projected into the same 5120-dimensional stream. They sit in the sequence beside text tokens, and the model conditions on them exactly as it does on text. The prediction target remains text.

:::warning
The classic wrong turn with MTP is to read it as "this model emits four tokens per step, so decoding is four times faster." It does not. MTP is a training-time objective. What it buys at inference is a native drafter: the extra heads propose candidate continuations, and the main model still has to verify them, exactly as in speculative decoding ([lesson 7.5](/lessons/7-inference-and-efficiency/7.5-beam-search-speculative-decoding-and-medusa/)). If few proposals are accepted, you have paid for guesses you throw away and gained nothing. The speedup is an empirical question about the acceptance rate, never a property of the objective.
:::

## How do the other objectives hide the text?

The alternatives matter because they show what causal language modelling gives up. Each one hides part of the text in a different way. Here is each applied to "the cat sat on the mat".

- **Masked language modelling** (MLM), associated with BERT, corrupts selected input tokens: "the [MASK] sat on the mat". A bidirectional encoder, a model whose positions attend in both directions, must recover "cat". Every position sees the full context on both sides, which gives rich representations. But only the selected tokens carry the reconstruction loss, so each example produces fewer training signals than next-token loss does.
- **Span corruption**, used by T5, removes contiguous stretches and marks each gap with a sentinel, a special placeholder token: "the ⟨X⟩ on the mat". An encoder–decoder model then writes out the missing passage: "⟨X⟩ cat sat". Rebuilding whole passages resembles summarization or completion more than filling isolated blanks does.
- **Fill-in-the-middle** (FIM) keeps ordinary next-token cross-entropy but rearranges each document into prefix, suffix, then middle: the model reads "the cat" and "the mat" first, then writes "sat on". An autoregressive decoder (one that generates left to right) thereby learns insertion, which is the shape of most real code editing.

## Why is the data plumbing part of the objective?

These are not interchangeable labels, because the objective lives in many small pieces that must agree: masks, special tokens, packing (concatenating several documents into one fixed-length training sequence), target construction, and loss masks (which positions count toward the loss). Each disagreement breaks something specific:

- A visible MLM target leaks the answer.
- FIM boundary tokens that differ between training and inference make the arrangement unrecognizable.
- Concatenating unrelated documents without separators teaches transitions that never occur in real text.
- Loss computed on padding (filler tokens that only make sequences the same length) wastes signal.

So the tokenizer configuration is part of the objective contract, not preprocessing that happens beforehand.

:::caveat
There is no technical report for Qwen3.8-27B. The objective facts above come from the model card and config. The training-token count, data mixture, knowledge cutoff, and training compute are not published. Any lesson, blog post, or benchmark table that states them for this model is inferring, and should say so.
:::

## How do you mix and evaluate objectives?

Mixtures are possible and common: a decoder can see ordinary causal examples plus a fraction of FIM-transformed ones. The mixture weights decide how scarce compute is split between skills, so they belong in the run log and the evaluation, not in a preprocessing script nobody reads.

Evaluate each model on the task it practised: causal perplexity for left-to-right models, reconstruction for corruption objectives, and exact infilling or code tests for FIM. Losses under different objectives are not comparable, because the targets and the visible information differ.

Carry one question into the rest of this track: which prediction game consumes every unit of compute? For this model the answer is next-token prediction over 248,320 classes, with MTP heads looking further ahead and vision patches sharing the sequence. The architecture limits which games are possible; the objective picks the one that gets rewarded on every training token there was. How many tokens that turned out to be, this model has never published.
